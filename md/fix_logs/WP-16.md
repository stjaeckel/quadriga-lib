## Per item

**B-109** (D1). New helper `qd_sos_share_memory(a, b)` (`quadriga_lib_helper_functions.hpp:621`): true if the
half-open ranges `[memptr, memptr + n_elem)` of two matrices overlap, false if either is empty; the addresses are
compared as `std::uintptr_t`, since the pointers may belong to different blocks.
- `sos_val` (`src/sos_val.cpp:406-411`): each input (`freq`, `phase`, `pos`, `pos_b`, `phase_b`, `acf`, `dist`) is
  rejected when it is `val` itself (unchanged) or shares memory with `val` (was: equal start address). The check
  stays where it was, after the argument checks and before the first resize or write, so `val` and all inputs stay
  unchanged. Message now `Output 'val' cannot be an input or share memory with one.` (was `... cannot be the same
  object as an input.`). The documentation sentence (`:304-305`, "nor use the memory of one") is unchanged, as D1
  says; it now holds.
- `sos_remove_bias` (`src/sos_remove_bias.cpp:154-164`): every pair of arguments in which at least one is written
  (`phase`, `phase_b`, `offset`, `mean_before`) against all others (`freq`, `pos`, `pos_b`, `acf`, `dist` and the
  written ones) must not share memory: 9 arguments, at most 36 pairs, constant per call. In addition `offset` and
  `mean_before` cannot be the same object (both are always written; as the same object the offsets were silently
  replaced by the means). The old identity test `phase_b == &phase` is removed: for the non-empty `phase` it is a
  case of the overlap test. The check comes after all other argument checks, before anything is written.
  Messages: `Input 'phase_b' cannot share memory with 'phase'.` (was `... cannot be the same object as 'phase'.`),
  generally `Input|Output '<later argument>' cannot share memory with '<earlier argument>'.`, and
  `Outputs 'offset' and 'mean_before' cannot be the same object.`
  - Identity is checked only for `offset` / `mean_before`; an empty optional argument that is the same object as
    another one (e.g. one empty matrix passed as `pos_b` and `phase_b`, meaning one device) is still accepted, as
    before, because nothing is written to it before it was read.
  - Documentation corrected: the description now says that the written arguments cannot share memory with another
    argument, not even in part, and that such a call throws and leaves all arguments unchanged; the `phase_b`
    entry says "no memory shared with `phase`" (was "not the same object").
  - MEX and Python blocks: no change. Both wrappers copy `phase` and `phase_b` and allocate `offset` /
    `mean_before` themselves, so no wrapper call can reach the check.
- Other SOS functions (D1, checked, not changed): no other start-address-only test. `sos_acf_2d`, `sos_acfi`,
  `sos_acf_estimate` copy their inputs before the first output is resized (comments at `sos_acf_2d.cpp:66`,
  `sos_acfi.cpp:57`, `sos_acf_estimate.cpp:180`); `sos_calc_mse` and `sos_generate` write their outputs after the
  inputs are read; `sos_randn` / `sos_rand` / `sos_randi` convert `pos` / `pos_b` to local copies before `val` is
  resized and call `sos_val` on locals only; `sos_map` passes a matrix on the map memory to `sos_val` in its
  one-block path, so the new check now also applies there (see "Found on the way").

## Behaviour changes for users

- `sos_val` (C++): an output `val` that shares any part of the memory of an input (e.g. a matrix on foreign
  memory that starts inside `pos`) now throws `std::invalid_argument` before anything is written, as the
  documentation said; before, only the same object or the same start address was rejected and the call could
  return wrong values. Message now `Output 'val' cannot be an input or share memory with one.` (also for the same
  object). Not reachable from MATLAB / Octave / Python.
- `sos_remove_bias` (C++): `phase`, `phase_b`, `offset` and `mean_before` cannot share memory with another
  argument, not even in part, and `offset` / `mean_before` cannot be the same object; such calls now throw before
  anything is written (before, only `phase_b == &phase` was rejected). Message for `phase_b` / `phase` now
  `Input 'phase_b' cannot share memory with 'phase'.`. Documentation corrected. Not reachable from the wrappers.
- `sos_map` (C++): a map whose cubes lie in one block of memory that overlaps `freq` or `phase` now throws (through
  `sos_val`, message naming `val`) instead of computing on partly overwritten inputs.
- `sos_randn`, `sos_rand`, `sos_randi` (C++, MATLAB / Octave, Python): an unknown preset is reported as
  `Input 'preset' is not a known preset.` (was `Input 'name' ...`). `sos_preset` keeps `Input 'name' ...`.
- Valid calls: results unchanged (bit-identical hashes).
