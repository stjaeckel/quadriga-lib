## Per item

**B-026 (AVX2 sin/cos for large arguments).** All AVX2 sin/cos kernels now share one polynomial part
(`_fm256_sincos_poly_ps`, Cephes polynomials and quadrant signs; index given as octant or quadrant). Float input
(`_fm256_sincos256_ps`): lanes with |x| <= 2^22 use the old float Cody–Waite reduction (measured: 1.3e-7 up to 2^22,
4e-5 in [2^23, 2^24), garbage above); a per-vector compare sends lanes above 2^22 (and inf) to a double-precision
quadrant reduction (q = round(x * 2/pi) kept in double, two-constant split of pi/2, quadrant bits from the mantissa of
q + 1.5 * 2^52, so no int32 overflow), blended per lane, so a lane's result never depends on its neighbours. Double
input (`_fm256_sincos256_pd`): unchanged double octant reduction; lanes where the int32 octant index overflows
(|x| > 1.68e9, inf, NaN) are detected from the sign of that index (no extra compare) and recomputed by the
large-argument path. Above 2^37 a lane is first reduced by multiples of 2*pi (repeatedly beyond 2^45 * 2*pi, where one
step is not exact), so |s|, |c| <= 1 for every finite input; inf gives NaN. Results for |x| <= 2^22 (float) and
|x| <= 1.68e9 (double) are bit-identical to the old kernels (2.5 million random blocks compared, `probe/ident.cpp`).
Accuracy (float and double): 1.3e-7 up to 2^38, 1.7e-7 at 2^42. In the loops of `fast_sincos` and `fast_geo2cart`
(float), blocks of 256 vectors are scanned first and run the old loop if no lane is large; otherwise small and large
vectors run in separate inner loops. Both measures were needed to keep the small-argument path at the old speed
(see "Performance"). The baseband DFT helper of WP-04 now calls the shared core (`_fm256_sincos_2pi_reduced_ps`,
bit-identical; its local copy is removed). Users that only see bounded arguments (SLERP: w * Phase in [0, pi]) call
the small-argument kernel directly.

The WP-04 note says both DFT kernels round with the magic-number trick; that holds for the generic kernel only (the
AVX2 DFT kernel uses `_mm256_round_pd`). The comment "exact only without -ffast-math" was added to the generic
`qd_sincos_2pi_reduced` and `qd_DFT_GENERIC`, and to the new quadrant reduction, which uses the trick itself.

**B-037 (low-amplitude AVX2 interpolation).** `_fm256_slerp_complex_ps` has a new argument `zero_if_both_tiny`. The
antenna interpolation passes `false`: where both amplitudes are below 1.19e-7 the linear result is returned, as in
the generic kernel. `fast_slerp` keeps the documented zero (its generic counterpart `slerp_complex_mf` zeroes too).
A-03 now: scale 1e-8 gives 2.354853 2.019394 1.292356 (AVX2) vs 2.354853 2.019394 1.292355 (generic).

**B-074 (`use_kernel`).** `fast_geo2cart` and `fast_cart2geo` throw "Input 'use_kernel' must be 0, 1 or 2." for other
values and the existing "AVX2 kernel requested but not available ..." for 2 in builds without AVX2 (the check now
also exists in the generic build). `ray_triangle_intersect` and `ray_point_intersect` throw "Input 'use_kernel' must
be 0, 1, 2 or 3." (2 and 3 already threw when unavailable); only the else branch of the kernel selection changed.
MEX and Python pass the exception through (`ValueError` in Python).

**B-075 (atan2 / cart2geo special values).** `_fm256_atan2256_ps`: both-infinite input is mapped to the diagonal
(pi/4, 3pi/4 with signs); NaN in x or y gives NaN (min / max drop a NaN, so the result is or-ed with the unordered
mask); the x < 0 fixup uses the sign bit, so atan2(±0, -0) = ±pi as in IEEE / std::atan2 and the generic kernel (the
documented "±0" was AVX2-only behaviour). The double-input `fast_cart2geo` AVX2 path computes the length and z / len
in double precision and scales x, y by 1 / len before narrowing (new `_fm256_cart2geo_pd`), so (1e-23, 1e-23, 1e-23)
gives el = 0.6154797, len = 1.732051e-23 and (1e20, 1e20, 1e20) el = 0.6154797, len = 1.732051e20; `len` is now
returned in double precision. Docs: range [-pi, pi] and the special values in C++ (`fast_atan2`, `fast_cart2geo`),
MEX `cart2geo` and Python `cart2geo` (the two wrong claims were only in the C++ block; MEX and Python got the
special values and the precision note).

**B-076 (SLERP fast path).** The old fast path (all 8 lanes with cos Phase > 0.99998) returned the linear interpolation
of the complex values. Besides the Φ²/8 amplitude error of the item, this weights the direction by the two
amplitudes; with unequal amplitudes the relative error reached 1.1e-3 (measured, `probe/slerpacc.cpp`), more than
the item says. Now nearly parallel lanes use the linear interpolation of the unit directions, times
(1 + wA wB (1 - cos Phase)) (exact first-order normalisation, error 4e-11) and the interpolated amplitude, per lane:
the fast path (all lanes near) and the blend in the general path give the same lane result. D-9: lane 0 is
0.999996841 / 0.002499997, |X| - 1 = -3.4e-8, with and without the different lane 7. A first version that normalised
the complex linear result showed the amplitude weighting in the area-A sweep (random patterns, AVX2-vs-generic up to
3.6e-3); fixed before the final runs. Measured relative error of the AVX2 SLERP vs double precision: 4.4e-7 for
Φ < 0.0063 (old 1.1e-3), 5.3e-7 up to 2 rad, 1.2e-5 for 2-3 rad, 8e-4 near pi (unchanged); the `fast_slerp` doc
("~5 ULP") now states these values.

## Behaviour changes for users

- `fast_sincos` and `fast_geo2cart` (C++, MATLAB, Python; AVX2 kernel) give correct values for large angles: max error
  1.3e-7 for |x| up to 1e10 (before: wrong above about 8e6 for float, inf / NaN above 1.7e9 for double), results stay
  in [-1, 1] for all finite input, and inf now gives NaN (before -inf / NaN). The same holds inside the AVX2 antenna
  interpolation of `get_channels_spherical(use_avx2 = true)`. Float input with |x| > 4.2e6 takes about 1.4-1.5 times
  as long as before (about 2 times when small and large values alternate within 8 elements); all other cases run at
  the old speed.
- `fast_atan2` and `fast_cart2geo` (AVX2 kernel): NaN input gives NaN (before pi/4); atan2(±inf, ±inf) gives ±pi/4 or
  ±3pi/4 (before NaN); atan2(±0, -0) gives ±pi as in the generic kernel and std::atan2 (before ±0). This also affects
  the azimuth of directions with x = -0 in the AVX2 antenna interpolation. The documented range is now [-pi, pi].
- `fast_cart2geo` with double input and the AVX2 kernel: `len` is computed and returned in double precision (before
  rounded to float), and vectors whose squared components under- or overflow in float (|component| below about 1e-19
  or above 1e19) get correct angles (before el = 0 and len = 0 or inf).
- Invalid `use_kernel` values now throw `std::invalid_argument` (MATLAB error, Python `ValueError`) instead of
  running the auto kernel: `fast_geo2cart`, `fast_cart2geo` (allowed 0, 1, 2), `ray_triangle_intersect`,
  `ray_point_intersect` (allowed 0, 1, 2, 3). `fast_geo2cart` / `fast_cart2geo` with `use_kernel = 2` in a library
  built without AVX2 now throw (as documented) instead of running the generic kernel.
- AVX2 antenna interpolation (`get_channels_spherical(use_avx2 = true)`): patterns whose field amplitudes are below
  1.19e-7 around the query are interpolated instead of returning 0; nearly parallel neighbouring samples are
  interpolated with correct amplitude and direction (before: up to 1e-3 relative error when the amplitudes differ).
  Coefficients change by about 1e-8 relative for normal patterns.
- `fast_slerp` (AVX2): nearly parallel inputs are accurate to 4.4e-7 relative (before up to 1.1e-3), and an
  element's result no longer depends on the other elements of its group of 8. Inputs with both amplitudes below
  1.19e-7 still give 0.
