## Per item

**B-024.** `xpr_update` keeps the parallel loop for unique indices and runs serially, in update-index order, when
`ray_index` holds a value twice. The check runs only where it matters: in the parallel branch (>= 2048 updates), with
`ray_index`, and when more than one OpenMP thread would run (one thread already processes the updates in order).
`has_duplicate_index`: one pass that accepts a strictly ascending index list (the usual case; `calc_diffraction_gain`
compacts its spine rays in order), otherwise a bitset of the columns when it has no more 64-bit words than there are
updates, else a sorted copy of the indices. Memory is O(n_rayU) in all cases, never O(n_ray). Unique indices give
bit-identical results (X1, X2 checksums), duplicates give the single-thread result for any thread count (test, C-8).
Documented in the `ray_index` entry.

**B-025.** At an interior point the unnormalised cross product of `-d` and `f` is tested: below 1e-10 (unit vectors,
i.e. a turn within 1e-10 rad of 0 or 180 deg) the two segments are treated as collinear. Then `g` is set to `u` (any
normal; it is not used for a rotation), the projection is skipped and the ring is carried over to the next vertex
(`fbs = ring + v1`), and `u` is kept for the next segment. A reversal is a split anyway (the angle between `d` and `f`
is below 10 deg), so the projection was never used there; only `g` and the `u` rotation were NaN. Both `acos`
arguments are clamped to [-1, 1]. Otherwise `g` is normalised with the same formula as `crossp(..., true)`, so all
other paths are bit-identical (T1). Note for the test: the ring at a 1e-9 rad bend still goes through the projection,
which uses `ray_triangle_intersect` in single precision; its deviation from the exact ring is 1.7e-7 m at 10 m, the
test allows 1e-6 there.

**B-061.** `sum(no_interact_1 / _2)` is summed as `arma::uword`; `interact_coord_1 / _2` must have that many columns
and 3 rows (with no interactions any empty matrix is accepted, e.g. `0x0` from a wrapper). The message names the input
and the expected column count.

**B-062.** The four aligned accesses of `qd_DFT_AVX2` are `loadu` / `storeu`; `freq`, `Hr`, `Hi` are Armadillo
vectors (`fill::none`, so no extra initialisation): no `aligned_alloc`, a failed allocation throws `std::bad_alloc`,
and the buffers are freed on any exit. The function returns after validation and output sizing when no output is
requested. The transpose copy into the outputs is unchanged. B1-B3 are bit-identical and not slower (Performance).

**B-065 (remainder).** `calc_angular_spreads_sphere`: `quantize` must be 0 or finite and >= 1e-3 deg
(`std::invalid_argument` otherwise, checked once before the CIR loop); the `int` casts in the quantiser are then
bounded by 180 000 (comment). `calc_delay_spread`: `granularity` must be finite and >= 0 (NaN was silently treated as
0 before); with `granularity > 0` every delay must be finite and `(global max - global min) / granularity < 2^53`
(computed in double). One addition to D5: when `global min / granularity` overflows the floating-point range (e.g.
float with a denormal granularity, or double with 1e-320) the grid origin would be infinite; this throws too ("Delays /
granularity exceed the floating-point range."). The bin indices are kept as doubles; there is no float-to-integer cast
left in the binning.

**B-066.** Sparse binning per CIR: keys `round((tau - min_delay_bin) / granularity)` (computed in `dtype` as before,
held as double, `+ 0.0` maps a -0 key to +0), sorted by (key, path index), so the powers of a bin are summed in path
order and the bins come in ascending order; bin delay `min_delay_bin + (dtype)key * granularity` as before (for
integer keys below 2^53 `(dtype)key` equals the old `(dtype)(uword)key`). The recursion then sees only the occupied
bins; empty bins of the dense profile contributed exact zeros to every sum and the threshold step gives the same
result (also for negative power maxima), so the results are bit-identical (test against the dense reference, S1
checksum). Sparse binning is used always: it is faster than the dense path for the benchmark (S1 0.38). Theoretical
difference: the old code dropped a path whose bin index exceeded the dense axis (possible only by rounding in
`ceil(max / g) * g`); the new code keeps it.

**B-067.** Each set with at least one finite value is recorded; a set without one gets a NaN column in
`cdf_per_set`. `cdf_avg`, `mu`, `sig` use only the recorded sets: with one recorded set the single-set path (so the
median with an extra all-NaN set equals the median alone, 49.005), with two or more the quantile averaging over a
compacted copy of their CDF columns (the copy is made only when a set was dropped; with all sets valid the loops are
the old ones, A1 bit-identical), with none NaN outputs (sizes `n_bins` / 9 / 9). User bins must be finite and strictly
ascending (`std::invalid_argument`); one bin is accepted. Documented in C++, MATLAB and Python.

**B-070.** Documentation only (decision (a)): `center_frequency` is the EM-equivalent frequency in scalar mode,
`f_eq = f_acoustic * c_light / c_sound`, with the constants of `qd_atmospheric_absorption.hpp`; also corrected in the
`apply_phase` entry (the wavelength is `c_light / center_frequency` in both modes) and the `apply_fspl` entry (`alpha`
is evaluated at the acoustic frequency `center_frequency * c_sound / c_light`, as the code does at line 631). The new
test pins the documented unit (phase -pi for half an acoustic wavelength at `1000 * c_light / c_sound`, ~0 at 1000).

**B-083.** The index search finds the first grid value greater than the query with `std::upper_bound` for grids of
more than 16 values and keeps the linear scan for up to 16 (the same index in both cases, also with repeated values,
so all results are bit-identical: I1-I3 checksums, test against the old scan). The threshold keeps I3 (n = 10) on the
old code path. `qd_arrayant_generate` and the other library callers get identical results (Catch2 suite unchanged).
The dummy y-axis of `interp_1D` is now zero-initialised explicitly (`arma::Col(1)` relied on Armadillo's default zero
fill; a NaN there would now turn every output into NaN).

**B-107.** A NaN query gives NaN weights for its output sample (1D: that entry; 2D: the whole output column / row of a
NaN x / y query). The NaN test runs only where a NaN query ends (index 0 for the scan, n for the binary search), so
the common path has no extra comparison. The clamping is documented in the C++ block and the MATLAB `interp` block
(Python has no interp wrapper).

**B-120.** Convention (D11): `c(r, t) = r^T M t`, the coupling of `get_channels_spherical`
(`qd_coeff_combine`, `src/quadriga_lib_helper_functions.hpp:516-526`, multiplies `Vr * M * Vt` without conjugation),
with `P1 = (V, H) = (1, +j)/sqrt 2`, `P2 = (1, -j)/sqrt 2` at both ends. Then
`M_P1P1 = (M_vv - M_hh + j(M_vh + M_hv))/2`, `M_P2P2 = (M_vv - M_hh - j(M_vh + M_hv))/2`,
`M_P1P2 = (M_vv + M_hh + j(M_hv - M_vh))/2` (receive P1, transmit P2), `M_P2P1 = (M_vv + M_hh + j(M_vh - M_hv))/2`.
These are exactly the old expressions relabelled (old LL = new RL, old RL = new RR, old LR = new LL, old RR = new LR),
i.e. the old code used `r^H M t`. Columns 4 / 5 are per receive polarisation: LHCP = sum|M_LL|^2 / sum|M_LR|^2, RHCP =
sum|M_RR|^2 / sum|M_RL|^2; column 3 = (LL + RR) / (LR + RL). For finite data the new power sums equal old ones
bit-for-bit (same expressions, same order), so new col 3 = 1 / old col 3, new col 4 = 1 / old col 5, new col 5 =
1 / old col 4 (up to the 0 / Inf rules). Columns 0-2 and `pg` are bit-identical (P1 checksums).

Naming (derivation):
1. The library's polarisation basis is the standard spherical one. `qd_arrayant_interpolate`
   (`src/qd_arrayant_interpolate_avx2.cpp:416`, same in the generic kernel) uses, for azimuth `phi` and elevation
   `theta` (0 at the horizon), the direction `r = (cos th cos ph, cos th sin ph, sin th)`,
   `e_theta = (sin th cos ph, sin th sin ph, -cos th)`, `e_phi = (-sin ph, cos ph, 0)`. With the zenith angle
   `theta_z = pi/2 - th` this is the textbook `theta-hat`; `e_theta x e_phi = r` (e.g. at ph = th = 0:
   (0,0,-1) x (0,1,0) = (1,0,0)). So (e_theta, e_phi, outward direction) is right-handed, like (x, y, z).
2. Time convention: the coefficients are `c * exp(-j k d)` (`qd_coeff_combine`: re*cos + im*sin, -re*sin + im*cos),
   i.e. `exp(-j 2 pi f tau)`, which is a delay for `exp(+j 2 pi f t)`.
3. A transmit pattern `(E_theta, E_phi) = (1, +j)` radiates along `r`, so `E(t) = Re{(e_theta + j e_phi) exp(j w t)}
   = e_theta cos wt - e_phi sin wt`: the field turns from `e_theta` towards `-e_phi`, i.e. clockwise about `r` in the
   right-hand sense (the right-hand rule about `r` turns `e_theta` towards `+e_phi`). Seen along the propagation
   direction this is left-handed: P1 = LHCP by the IEEE definition, P2 = RHCP.
4. Receive side: the RX pattern is evaluated in its own frame with the outward direction pointing to the source; by
   reciprocity an antenna whose transmit pattern is LHCP receives LHCP. Check with the LOS: TX along +x, RX frame
   `e_theta` equal, `e_phi` reversed, hence `M = diag(1, -1)`; an LHCP wave `(1, +j)` arrives as `(1, -j)` in RX
   components and couples to the RX pattern `(1, +j)` with `(1, j) . (1, -j) = 2`, i.e. |c| = 1 (co-polar), as
   `get_channels_spherical` gives in repro B-120 and in the new test. The frames settle the naming; no question left.

The old pinned case explained the 0 by "a single reflection reverses handedness"; the LOS matrix is not a reflection.
In the library's frames a single ideal reflection looks like `diag(1, 1)` relative to the LOS `diag(1, -1)` (one
component mirrored), which the corrected identity-matrix case now reports as cross-polar (0).

## Behaviour changes for users

- `calc_cross_polarization_ratio` (C++, MATLAB, Python): the circular columns are redefined. The circular entries
  couple the same circular vector at both ends through `M` as the channel generators do (`r^T M t`, LHCP = (V, H) =
  (1, +j)/sqrt 2, RHCP = (1, -j)/sqrt 2); LHCP-XPR and RHCP-XPR are per receive polarisation (like V-XPR / H-XPR).
  The LOS matrix `diag(1, -1)` now gives Inf (co-polar) instead of 0; in general new column 3 = 1 / old column 3,
  new column 4 = 1 / old column 5, new column 5 = 1 / old column 4. Columns 0-2 and `pg` are unchanged.
- `calc_angular_spreads_sphere` (C++), `calc_angular_spread` (MATLAB, Python): `quantize` must be 0 or a finite value
  >= 1e-3 deg; negative, NaN, Inf and 0 < quantize < 1e-3 now throw / raise (before: negative and NaN meant "off", tiny
  values ran into undefined integer casts).
- `calc_delay_spread` (C++, MATLAB, Python): `granularity` must be finite and >= 0 (NaN meant "off" before, Inf was
  undefined); with `granularity > 0` all delays must be finite and the delay span / granularity below 2^53, else
  `std::invalid_argument` / error / `ValueError`. Memory no longer grows with the delay span (50 CIRs over 1 ms at
  1 ns: 4 MB instead of 808 MB); results are unchanged.
- `acdf` (C++, MATLAB, Python): a data set without finite values gets a NaN column in `cdf_per_set` (before: zeros)
  and is left out of `cdf_avg`, `mu` and `sig` (before: it biased them, e.g. the median of 0..99 became 74.2 instead of
  49.0); if no set has finite values (user bins), these outputs are NaN. User bins must be finite and strictly
  ascending, else an error (before: accepted, wrong CDF).
- `interp_1D` / `interp_2D` (C++), `interp` (MATLAB): a NaN output sample point gives NaN (before: the first data
  value); the constant extrapolation outside the grid is now documented. Long grids are much faster (160 000 samples:
  6 ms instead of 3-6 s); results are otherwise unchanged.
- `xpr_update` (C++): duplicate `ray_index` entries are applied one after the other in update order, giving the
  single-thread result for any thread count (before: a data race with >= 2048 updates and several threads); such calls
  run single-threaded.
- `path_to_tube` (C++): paths with collinear interior points (straight continuation, exact reversal) give finite
  meshes; the ring is carried over unchanged (before: NaN vertices). Other paths are unchanged.
- `combine_irs_coord` (C++): `interact_coord_1 / _2` must be `[3, sum(no_interact_1 / _2)]` (empty when the sum is
  0), else `std::invalid_argument` (before: heap over-read or an unrelated bounds error).
- `baseband_freq_response` (C++): no `aligned_alloc` any more; an allocation failure throws `std::bad_alloc` (before:
  segfault); a call without outputs returns after the input checks.
- `calc_diffraction_gain` (C++): documentation only: in scalar mode `center_frequency` is the EM-equivalent frequency
  `f_acoustic * c_light / c_sound` (the MATLAB / Python wrappers keep taking the acoustic frequency).
