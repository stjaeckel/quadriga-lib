## Per item

**Central change (`src/mex_helper_functions.hpp`).** New helpers:
- `qd_mex_check_input(input, var_name, max_dims)`: rejects complex (unchanged message), sparse and more than
  `max_dims` dimensions. Called by `qd_mex_get_dims` (4 dimensions) and therefore by every reinterpret, typecast and
  `get_*` reader, by the three `qd_mex_matlab2vector_*` (which now use `qd_mex_get_dims` instead of their own
  dimension code), by `qd_mex_get_scalar`, by `qd_mex_anycast` (3 dimensions) and by `qd_mex_matlab2vector_Bool`
  (any number of dimensions, it reads by element count).
- `qd_mex_fits<dtype>(v)` / `qd_mex_cast<dtype>(v, bad)`: conversion of one value; for integer targets (not bool)
  NaN, Inf, fractions and values outside the type range set a flag and give 0 (no undefined cast). Integer sources are
  checked against the range only; float targets and same-type copies compile to the plain cast. All conversion loops
  (`qd_mex_copy_convert`, `qd_mex_typecast_CubeVec`, the 72 loops of the `qd_mex_matlab2vector_*`) run one pass with
  the flag and raise the error after the loop.
- `qd_mex_integer_error<dtype>`: "Input 'x' must be an integer from 0 to 4294967295." (scalar) or "Entries in 'x'
  must be integers from 0 to 18446744073709551615." (array); without a name "Input must be ..." / "Entries must be ...".
- `qd_mex_read_scalar` (internal) + `qd_mex_get_scalar(input, var_name, default)`: reads every MATLAB class without a
  detour through double (uint64 / int64 keep their value) and applies the check.
- `qd_mex_get_seed(input, var_name = "seed")`: the shared seed reader, see B-034.
- An optional `var_name` argument for `qd_mex_get_Col/Mat/Cube/CubeVec` (third argument, after `copy`),
  `qd_mex_reinterpret_*` (third), `qd_mex_matlab2vector_*` (third), `qd_mex_matlab2vector_Bool` and
  `qd_mex_get_strings` (second), `qd_mex_get_dims` (second), so that the new messages name the argument. The wrappers
  with integer inputs, the channel-struct reader and the arrayant-struct reader in `src/mex_quadriga_lib_functions.hpp`
  pass their names.

**B-030.** Sparse input is rejected centrally: "Sparse inputs are not supported." or, with a name, "Input 'x' is sparse;
sparse inputs are not supported." No conversion to full (manager default). The repro `F-2` ASan what-if (built against
`build_asan`) now gives no report; the call errors before the C++ function runs.

**B-032.** `channel_export_obj_file` requires `no_interact` and `interact_coord` to have one entry per snapshot of the
coefficients (`!=` instead of the old `>` for `interact_coord`, new check for `no_interact`), before the loop that read
`no_interact[i]`. Messages: "Number of snapshots in no_interact must match coefficients." and the existing
"Number of snapshots in interact_coord must match coefficients.".

**B-033.** `qd_mex_get_strings` checks each cell element: NULL (unset element in MATLAB) or a non-char element raises
"Cell element i of 'x' is not a string." (1-based i). `qd_mex_get_string(nullptr)` raises "Input must be a string
(character array)". Deviation, deliberate: an explicit `[]` element (`{'a', []}`) is also rejected. Octave stores an
unset element of `cell(1,1)` as `[]`, so rejecting only NULL would make `cell(1,1)` an error in MATLAB and an empty
name in Octave; with this rule both behave the same. An empty char `''` is still a valid (empty) name.

**B-034.**

## Behaviour changes for users

Every change is a new `quadriga_lib:CPPerror` for input that was silently wrong (or crashed) before. Valid input gives
the same results as before.
