## Behaviour changes for users

- C++ `qrt_file_read`: `aod`, `eod`, `aoa`, `eoa` are now filled when requested without `path_gain`/`path_length`.
  Before, they kept the caller's old contents.
- C++ `qdant_write_multi`: invalid input throws and leaves an existing file untouched (before: the file was deleted).
- MATLAB on Linux: all `.mexa64` files are linked with `-z nodelete`. Once loaded, a MEX file stays mapped until
  MATLAB exits (`clear mex` no longer unloads it). A rebuilt MEX file needs a MATLAB restart. R2026a no longer
  crashes at exit after HDF5 calls.
- MATLAB/Octave `qrt_file_read` and `hdf5_read_channel` no longer change a `uint64` `i_cir` / `snap` variable of the
  caller.
- MATLAB/Octave `fast_sincos(x, [])` returns the sine (before: cosine). The outputs are single, now documented.
- MATLAB/Octave `arrayant_qdant_write` with separate inputs and `center_freq = []` writes 299792458 (before: NaN).
- MATLAB/Octave `qrt_file_read` doc: `interact_type` is uint8 (doc only; the type did not change).
