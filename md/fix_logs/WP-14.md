## Per item

**B-018 (D1).** `obj_file_write` writes `usemtl (null)` before a face with `mtl_ind = 0` that follows a face with a
material in the same written block (object, or part with `split_loose_parts`); consecutive faces without material share
one marker, and the next face with a material writes its `usemtl` again. The check runs in the face loop of the written
order, so it works unchanged after the part reordering of `split_loose_parts` (test section "split_loose_parts"). A
face without material at the start of a block needs no marker (the reader resets the material at `o`). Files without
such a switch are byte-identical to the old writer (O2 checksum). `obj_file_read` maps `usemtl (null)` to 0 in `mtl_ind`
and `csv_ind`, before the table lookup (so also with `csv_strict`), and does not intern it (not in `mtl_names` /
`bsdf`); the `.mtl` gets no `(null)` entry (`used_mtl` holds only materials > 0). Faces are not reordered and objects are
not split. Round 2 (manager's decision): a material named `(null)` that is used by at least one face throws
`std::invalid_argument` ("Material name '(null)' is reserved for faces without material; rename it.") in the input
validation, before anything is written; unused entries of `mtl_names` may carry the name.

**B-057 (D2).** (b) Every line of the OBJ (both passes) and of the MTL scan has a trailing `'\r'` removed
(`strip_cr`); the `newmtl` comparison also trims surrounding whitespace (`trim_ws`, as the `usemtl` names are trimmed),
so `newmtl blue ` matches `usemtl blue`. The material CSV reader had no such gap: `split_csv` trims every cell
(including `'\r'`) and blank `"\r"` lines are skipped; the CRLF test covers a CRLF CSV and passed before for that part.
(c)+(d) The face line is parsed by a small parser (`parse_face_refs`) instead of `sscanf("%llu")`: per reference an
optional sign and digits, then an optional `/vt/vn` part, at most 4 references, stopping at the first token that does
not start with an integer. Positive indices are 1-based, negative ones count back from the vertices defined before the
line (`-1` = the last one, OBJ definition). Index 0 and any index beyond the vertices defined so far (absolute or
relative, including overlong values, which saturate) throw `std::invalid_argument` ("... face N references a vertex
that is 0 or beyond the K vertices defined before it."), for every output combination, so `face_ind` can no longer
hold wrapped or out-of-range values. The check in the mesh assembly became redundant and was removed. The parser also
handles a mix of `v` and `v/vt/vn` faces in one file (the old code switched to the slash format for the rest of the
file after the first slash face and then rejected plain faces) and has no `sscanf` overflow UB. Lines the old code
accepted are accepted the same way (`f 1 2 3 # x`, `f 1 2 3x`, `f 1//1 ...`); the only differences are the new
negative indices and the stricter range checks. (e) The count-only shortcut is gone: without outputs the second pass
runs with nothing materialised and validates every face (a quad file throws). Also: a file with faces but without
vertices now throws (before: returned 0 with empty outputs, because `n_vert == 0` took the "empty mesh" exit); a file
without faces still returns 0. (f) untouched (B-104, WP-17). Documented in the C++, MATLAB and Python blocks; the
duplicated first bullet ("Parses a triangulated `.obj` ...") of both wrapper blocks was merged into the new text.

**B-058 (D3).** `write_png`: an empty matrix and a user range with `min_val > max_val` (both finite) throw
`std::invalid_argument` before any file is written. The auto range ignores NaN and +-Inf (`std::isfinite`); the range is
degenerate when `!(max > min)` or `max - min` is not finite (constant / 1x1 / all-NaN / all-Inf data, log input without
a positive value, user `min == max`, a user bound above or below all data, an infinite user bound), and then every
pixel gets the first colour. Otherwise NaN pixels get the first colour and +-Inf are clipped to the last / first
colour by the existing clipping. The float-to-integer cast only sees values in [0, n_cmap - 1]. Finite data in a
non-degenerate range take the old arithmetic unchanged (P1 checksum identical). The encoder error message now closes
its quote (B-104 point 5, one character in the same lines). Documented in the C++, MATLAB and Python blocks.

**B-056 (D4).** `mitsuba_xml_file_write`: `faces_by_object` groups the faces by object in one counting-sort pass
(ascending face order, as `arma::find(obj_ind == i)` returned them); it is used for the per-material split (original
objects), and again after the split for the PLY files and the material reference in the XML (first face of each
object). Per object the vertex IDs of its faces are sorted and made unique (`std::sort` + `std::unique`, the order
`arma::unique` gave), each gets its PLY-local index in a global `ply_index` array (written for the object's vertices
before its faces read it, so it needs no reset), and the faces are written through that array. This replaces the
per-vertex `find(vert_idx == i_vert)` and the per-object `find(obj_ind_local == i_obj)`. XML and PLY bytes are
identical: Catch2 case with a split object, a vertex shared by two objects and faces whose vertex order differs from
the ascending order, pinned to the output of the old writer (`mitsuba_ref/ref_old.txt`); M1 / M2 checksums identical.
The absolute PLY path stays (B-104 point 6, WP-17). Not changed: the per-material `find` in the `map_to_itu_materials`
remap (O(n_mtl x n_face), not part of D4).

**B-122 (D5).** `qrt_file_read_raw` grows the output geometrically: `reserve(max(size + nP, 2 * capacity))` only when
the next CIR does not fit (the first CIR reserves exactly its count). Before, `reserve(size + nP)` per CIR reallocated
and moved every path read so far for each CIR. Outputs identical (Q1 checksums); doubling the paths now doubles the time
(Performance).

## Behaviour changes for users

- `obj_file_write` (C++, MATLAB, Python): a face with `mtl_ind = 0` that follows a face with a material in the same
  object (or part with `split_loose_parts`) is now preceded by `usemtl (null)`; `obj_file_read` maps `usemtl (null)` to
  0 in `mtl_ind` and `csv_ind` (also with `csv_strict`) and does not list it in `mtl_names` / `bsdf`. A written mesh now
  reads back with the same material indices (before: such faces inherited the previous material). Files without such a
  switch are unchanged; face order and objects are unchanged; the `.mtl` has no `(null)` entry. A material named
  `(null)` that is used by a face is rejected (`std::invalid_argument` / error / `ValueError`).
- `obj_file_read` (C++, MATLAB, Python):
  - negative (relative) face indices are supported as the OBJ format defines them (`-1` = the last vertex defined
    before the face line), also in `v/vt/vn` references; faces may mix `v` and `v/vt/vn` references within a file;
  - index 0, or an index beyond the vertices defined before the face (including references to vertices defined later
    in the file), throws `std::invalid_argument` / error / `ValueError` for every combination of requested outputs
    (before: only when `mesh` was requested; with only `face_ind` the index was returned wrapped or out of range);
  - a call without outputs parses and validates the whole file (a quad file throws; before it returned the face
    count); a file with faces but no vertices throws (before: returned 0);
  - CRLF line endings are handled in `.obj` and `.mtl` (before: a CRLF `.mtl` gave an empty `bsdf`); `newmtl` names
    are compared without surrounding whitespace;
  - error message for bad face indices: "Error reading face data in '<file>': face N references a vertex that is 0 or
    beyond the K vertices defined before it." (before: "Error assembling triangle mesh from '<file>'.").
- `write_png` (C++, MATLAB, Python): the auto range ignores NaN and +-Inf; a degenerate range (constant, 1x1, all-NaN
  data, log input without positive values, `min_val == max_val`, an infinite bound) gives the first colour everywhere
  (before: the last colour, through an undefined NaN-to-integer cast); NaN pixels get the first colour (before: the
  last), +-Inf the last / first; `min_val > max_val` (both given) and an empty matrix throw `std::invalid_argument` /
  error / `ValueError` (before: an inverted range was silently collapsed, an empty matrix wrote an undecodable file).
  The encoder error message closes its quote.
- `mitsuba_xml_file_write` (C++, Python): much faster for large objects (80 000 faces in 16 ms instead of
  3.2 s); output unchanged.
- `qrt_file_read_raw` (C++): linear time in the number of paths per origin (240 000 paths in 18 ms instead of 1.4 s);
  output unchanged.
