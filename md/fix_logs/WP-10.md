## Per item

**B-012 (-100 dB floor).** The writer computes the power in dB of every sample without rounding and without floor:
`10 log10(re^2 + im^2)`, for powers below the smallest normal double `20 log10(hypot(re, im))`, and `-inf` only when
re and im are both exactly 0. A component is written when any sample is non-zero. An element that is zero in both
components is written as an all-`-inf` `EthetaMag` node (before: no node), so every element of a new file is backed by
pattern data (see B-042). The reader computes `sqrt(10^(0.1 x))` as before; for powers below the smallest normal
number of `dtype` (x below -3076.5 dB in double, -379.3 dB in float, values the old writer could not produce) it
computes the amplitude directly as `10^(0.05 x)` in double, so low-level float patterns (1e-20) do not underflow.
A-09: `read back 2.01e-06`, `sample 3e-6 read back as 3e-06`.

**B-038 (6 digits).** The stream precision is set per section: element positions, coupling magnitude and coupling
phase with `max_digits10` of `dtype` (17 / 9 digits, exact round trip of the stored value); pattern magnitudes (dB)
and phases (degree) with 15 significant digits for double and 9 for float; grids as before (rounded to 0.001
degree, 6 digits). The phase is no longer rounded to 1e-5 degree and no longer set to 0 below 1e-5 degree; -180 is
written as 180 as before. Choice of 15 digits: the dB value is then exact to 5e-13 dB for |x| < 1000 dB (5e-12 dB
up to the double range), i.e. the amplitude to 0.115 · 5e-12 = 6e-13 relative in the worst case, and the phase to
5e-13 degree; 14 digits would allow 6e-12 for levels below -1000 dB, 17 digits only add file size. Round trip of
the area-A probe `p5_qdant_roundtrip.cpp` (double, 3 elements, 2 ports, random polarimetric pattern), new library:
e_theta_re 2.8e-14, e_theta_im 6.5e-14, e_phi_re 3.4e-14, e_phi_im 4.7e-14, az / el 1.7e-14, positions 0,
coupling 3.4e-14 / 2.9e-14 relative (acceptance: 1e-12); old: 3.8e-6 to 8.6e-6 and 0.000211 m on the position.
Float: pattern 1.3e-7 to 1.4e-7, coupling 9e-8 to 1.5e-7, positions 0. Speaker multi-file: 5e-16 to 1.4e-15 (before
4e-6 to 6e-6). The remaining 1.7e-14 on grids and phases comes from the reader's constant `deg2rad =
0.017453292519943` (14 digits); it is kept so that old files read bit-identically (see "Found on the way").
A-10: `123.456789000 -> 123.456789000 (error 0 m)`, `coupling_re : 0.123456789 -> 0.123456789`.

**B-040 (ID 1 fallback).** The first `<arrayant>` node is used for ID 1 only when it has no `id` attribute (or an
empty one), i.e. files of other tools; otherwise a missing ID throws "Could not find an arrayant object with ID n in
the file." (the message now names the ID). The layout built for files without `<layout>` now reads the `id`
attribute (before: the first attribute of the node, whatever its name), with the same "no ID" rule. `qdant_read_multi`
probes ID 1 only for the layout and ignores the error, so it still reads files without ID 1 (covered by the test).
A-12: `read id=1: error 'Could not find an arrayant object with ID 1 in the file.'`.

**B-041 (layout reset).** Decision (b): no code change. The C++ `qdant_write` block, the MEX `arrayant_qdant_write`
block (bullet and `layout` default) and the Python `qdant_write` block (bullet and `layout` default) say that a
write without layout replaces the layout by a row of all IDs in file order and that a custom layout is lost unless it
is passed again. The test pins the reset for an append and for an overwrite of an existing ID. A-13 unchanged
(`1 2 3 4`), as decided.

**B-042 (unchecked counts).** The reader checks every count against data in the file before it allocates:
- `NoElements` must be a positive decimal integer (digits only, at most 2^32 - 1; before: `as_ullong`, so `-1`
  became 2^64 - 1, `1e3` became 1, `abc` became 0).
- The element count must be backed by data: `ElementPosition` (exactly 3 n values, as before), `CouplingAbs` (a
  non-zero multiple of n values; an empty `CouplingAbs` is now an error), or pattern nodes up to `el="n"`. All these
  lists are parsed before any allocation that depends on n, so the allocations are proportional to the file.
- Pattern nodes are collected in one pass over the children (before: one `find_child_by_attribute` per element and
  component, quadratic in the number of elements); each magnitude and phase node must have at least `2 n_ang - 1`
  characters for the grid size before the cubes are allocated.
- Values the reader creates without data are limited to 2^24 (128 MB in double): the zero patterns of elements
  without any magnitude node (number of such elements times the grid size; e.g. 256 elements on a 1-degree grid) and
  the identity coupling of a file without `CouplingAbs` (n^2, i.e. at most 4096 elements). Files written by the
  library always have `CouplingAbs` for validated arrays, and the new writer always writes a node per element, so
  only crafted or degenerate old files reach the limits (an old file in which more than 256 elements of a 1-degree
  pattern were all below -100 dB, data the old writer had already lost).
- Malformed number lists, layouts and IDs (Armadillo `std::logic_error`, `std::stoi` exceptions) are returned as
  error messages, so every malformed-file error is a `std::invalid_argument`; `std::bad_alloc` is passed on. Arrayant
  IDs are parsed strictly (digits only, at most 2^32 - 1) in the reader and in the writer's scan of an existing
  file.
A-14: `exception type St16invalid_argument: 'NoElements' (200000000) is larger than the number of elements found in
the file.`, `max RSS 4868 kB` (before: `std::bad_alloc` after 4.69 GB).

**B-045 (speed of light).** New last argument `dtype propagation_speed = 299792458.0` in
`arrayant<dtype>::combine_pattern` and `arrayant_combine_pattern_multi`; it replaces the hard-coded constant in the

frequencies. The existing MOxUnit error case "5 inputs = wrong number of inputs" now uses 6 inputs (5 inputs are valid).
A-17 (unchanged repro, default speed): `|p(az=90)| = 2.000`; the same repro with `propagation_speed = 344`
(`probe/a17_speed344.cpp`): `|p(az=0)| = 2.000   |p(az=90)| = 0.506   expected with c=344 m/s: 2.000 and 0.506`.

**B-047 (multibeam defaults).** Header defaults `M = 1`, `N = 1`. Checked: the C++ MD block (declaration and

## Behaviour changes for users

- QDANT writer (`arrayant::qdant_write`, `qdant_write_multi`, MATLAB `arrayant_qdant_write`, Python
  `arrayant.qdant_write`), file content:
  - pattern samples below -100 dB are written (before: dropped; elements entirely below -100 dB read back as zeros);
    exact zeros are written as `-inf`; an element that is zero in both components is written as an all-`-inf`
    `EthetaMag` node (before: no node);
  - element positions and coupling with full precision (17 significant digits in double, 9 in float; before 6);
    pattern magnitudes (dB) and phases with 15 significant digits (9 for float; before rounded to 1e-4 dB and 1e-5
    degree); phases below 1e-5 degree are no longer set to 0; a double round trip is exact to about 1e-13
    relative (before about 1e-5);
  - files of double patterns are about 2 times larger (1.8 to 2.3 in the examples), writing and reading take
    correspondingly longer (large pattern: write 1.08 s vs 0.88 s, read 0.57 s vs 0.43 s, provisional timing);
  - older library versions read the new files with the same values; old files read with the new library give
    bit-identical values.
- QDANT reader (`qdant_read`, `qdant_read_multi`, MATLAB `arrayant_qdant_read`, Python `arrayant.qdant_read`):
  - an ID that is not in the file is an error; before, ID 1 returned the first entry of the file whatever its ID.
    Python `qdant_read(fn)` (default ID 1) now raises for a file without ID 1 (e.g. one written with `id=2` only);
    MATLAB `arrayant_qdant_read(fn)` reads all entries and is not affected. The message names the ID ("Could not
    find an arrayant object with ID n in the file.");
  - malformed files raise `std::invalid_argument` (MATLAB error, Python `ValueError`) instead of
    `std::logic_error`, `std::out_of_range`, `std::bad_alloc`, or silently accepted values: invalid or unbacked
    `NoElements`, empty `CouplingAbs`, malformed number lists, layouts and IDs (an ID like `3abc` was read as 3);
  - limits: an entry may have at most 2^24 zero values for elements without pattern data (e.g. 256 elements on a
    1-degree grid) and, without `CouplingAbs`, at most 4096 elements; files written by the library are not affected;
  - for files without `<layout>`, the layout is built from the `id` attribute (before: the first attribute of each
    entry).
- `qdant_write` with an existing file that contains an invalid ID returns a clear error instead of an exception from
  `std::stoi`.
- `arrayant::combine_pattern` and `arrayant_combine_pattern_multi` have a new last argument `propagation_speed`
  (default 299792458, results unchanged in double; in float the default is 299792448, see B-045); C++ code that takes the address of these functions or links against an
  older binary must be recompiled. MATLAB `arrayant_combine_pattern`: optional 5th input (struct mode) or 16th input
  (separate inputs); a call with 5 inputs is no longer an error. Python: keyword `propagation_speed`. Non-positive or
  non-finite speeds throw.
- `generate_arrayant_multibeam` (C++ only): default `M = 1`, `N = 1` (before 2, 2); C++ callers that relied on the
  defaults get a single element instead of a 2 x 2 array. MATLAB and Python already used 1, 1.
- `qdant_write` without a layout replaces a custom layout in the file by a row of all IDs: unchanged, now documented.

## Found on the way

- `qd_arrayant_qdant_write` ignores the namespace prefix of an existing file: entries, names and pattern nodes are
  appended without the prefix (`src/qd_arrayant_qdant.cpp:442`, `492`, `503`, `514`, `672`, `684`; `append_child`
  with fixed names), so an entry appended to a file with `xmlns:xx="..."` cannot be read back ("Could not find an
  arrayant object with ID 2 in the file.", `probe/ns_prefix.cpp`). The reader handles the prefix. Not changed (old
  behaviour, outside the items).
- The reader's `deg2rad = 0.017453292519943` (`src/qd_arrayant_qdant.cpp:237`) has 14 significant digits; grids,
  coupling phases and pattern phases read with 1.7e-14 relative error. Kept, so that old files read bit-identically;
  a full-precision constant would change old-file values in the last digits.
- Malformed number tokens inside a list are read as 0 or as their numeric prefix without error (Armadillo parses with
  `strtod`: `abc` gives 0, `1.5x` gives 1.5). Not changed; only structural errors of a list raise.
- `qdant_read_multi` finds the unique IDs of the layout with a quadratic search
  (`src/qd_arrayant_xio.cpp:221-229`) and parses the whole file again for every ID, so the read time grows with the
  square of the number of entries. Not changed (performance, not memory).

### Number format: 6 decimals instead of 7 significant digits (differs from the manager's note)

The note asked for 7 significant digits for pattern magnitudes (dB) and phases. A dB value of 10 dB or more then
keeps only 5 decimals, and the amplitude error reaches 0.115 · 5e-6 = 5.8e-7 of the sample; when the element peak is
above 10 dB this is 5.8e-7 of the peak, which misses the acceptance of 1.2e-7. The manager's 3GPP pattern has its peak
at 8 dB (6 decimals), so it passed there. Measured with the round-1 files rewritten by several rules
(`r2/prec_rules.py`, `r2/prec_rules.txt`; error = largest error of the complex field relative to the element peak,
and per sample for samples above -100 dB of the element peak):

| Rule | 3GPP 8x8 dual-pol (peak 8 dB) | p5 random pattern (10.5 dB) | multibeam 8x8 combined (43.6 dB) | dipole (1.8 dB) |
|---|---|---|---|---|
| 15 digits (round 1) | 217.7 MB, 9e-15 | 0.030 MB, 5e-14 | 2.95 MB, 1e-14 | 1.16 MB, 1e-15 |
| 7 significant digits | 135.3 MB, 7.1e-8 (5.8e-7 per sample) | 0.017 MB, **7.0e-7** | 1.89 MB, **4.9e-7** | 0.642 MB, 8.4e-8 |
| 8 significant digits | 145.6 MB, 7.2e-9 (5.8e-8) | 0.018 MB, 7.5e-8 | 2.03 MB, 5.3e-8 | 0.708 MB, 1.2e-8 |

Chosen: magnitudes (dB) and phases (degree) rounded to 6 decimals, trailing zeros removed. The rounding step of 1e-6
dB gives at most 5.8e-8 of each sample's amplitude, at every level (half the float epsilon), the 1e-6 degree step
8.7e-9 rad; so every sample is as accurate as a float, not only relative to the peak. The size is 5% above 7 digits
for the 3GPP pattern and smaller than 7 digits for high-gain or low-gain patterns. Not chosen: phases with 5 decimals
(no saving on the 3GPP file, 1e-7 per sample on p5); decimals relative to the element peak (7% smaller on 3GPP, 24%
on the combined multibeam, but weak samples lose relative accuracy: 5.7e-4 at -100 dB). It is available if the size
matters more than the per-sample accuracy.

Element positions and coupling (magnitude, phase): the shortest text that reads back as the same float (C++
`std::to_chars(float)`, at most 9 significant digits = `max_digits10` of float), for float and double data. Grids
unchanged (0.001 degree). Center frequency unchanged (pugixml, 17 digits; one value per entry).

### Rule as implemented (per sample)

`src/qd_arrayant_qdant.cpp`, writer only (`qd_qdant_decimal_thresholds`, `qd_qdant_append_fixed`, `pattern_text`):
- Reference: the peak of the element in dB, the largest power over both components (e_theta and e_phi) of that
  element. A component far below the other is quantized relative to the element peak; an element entirely at a low
  level (the B-012 case) relative to its own peak.
- Budget: the absolute error of every complex sample after rounding stays at or below 6e-8 times the element's peak
  amplitude. Error terms for a sample of amplitude a, with magnitude step s (dB) and phase step t (degree):
  magnitude at most a (10^(s/40) - 1) (exact, not the linear 0.115 s/2; the two agree for small steps), phase at
  most a (1 + magnitude error) (t/2)(pi/180); they are orthogonal, so the total is the root of the sum of squares.
  The magnitude may use 97% of the budget, the phase the remainder.
- Decimals are chosen per sample (not per block): level = sample dB - element peak dB; the magnitude gets the fewest
  decimals k (0 to 6) with level <= T_mag[k]; the phase the fewest decimals kp with level <= T_phase[k][kp]. The
  thresholds are computed once from the error terms:

| k | T_mag[k] (dB below the element peak) | T_phase[k][k] / T_phase[k][k-1] |
|---|---|---|
| 6 | +0.10 (always for samples within 19.9 dB of the peak) | +0.26 / -4.82 |
| 5 | -19.90 | -19.74 / -24.82 |
| 4 | -39.90 | -39.74 / -44.82 |
| 3 | -59.90 | -59.74 / -64.82 |
| 2 | -79.91 | -79.74 / -84.83 |
| 1 | -99.93 | -99.76 / -104.87 |
| 0 | -120.16 | -120.00 |

  i.e. magnitudes have 6 decimals within 20 dB of the peak and one decimal fewer per 20 dB below it; phases about the
  same, 6 decimals only within 4.8 dB. Six decimals always satisfy the budget (a <= peak), so the cap of 6 never
  violates it.
- Values are written with `std::to_chars` (fixed, k decimals), trailing zeros and point removed, `-0` as `0`; exact
  zeros `-inf` (their phase `0`). A phase node is skipped when all its phases are written as `0`. An all-zero element
  keeps its all-`-inf` node. Positions, coupling, grids and the file structure as in round 2; the reader is unchanged.
