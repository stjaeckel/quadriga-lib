Notes
  • The Quadriga-Lib Python interface of implemented using pybind11. Before getting started, make sure that the Python library is compiled for your system and python environment.

  • Unless otherwise stated, the Quadriga-Lib Python API reads and writes data to and from Numpy arrays in double precision. Hence, you need to have numpy installed and imported in your python file.

  • There is currently no Microsoft Windows version of the Quadriga-Lib Python interface. This is planned for a later stage.

  • The Quadriga-Lib Python package is compiled into a single ".so" file located in the "lib" folder. To import it in Python, the "lib" folder must be on your Python path, which is usually not the case unless you install a package using pip or conda. To import the "quadriga_lib" from a custom location, you can do the following: 
    import sys
import numpy as np

sys.path.append("/path_to/quadriga-lib/lib")
import quadriga_lib

Array antenna functions


calc_beamwidth
Calculate the beamwidth and pointing angles of array antenna elements in degrees
  • Computes azimuth and elevation beamwidth at a given dB threshold (default 3 dB = FWHM)
  • Also returns the azimuth and elevation pointing angles of the main beam
  • Sub-grid resolution is achieved by bilinear interpolation of the field pattern (≈100x finer grid in each direction than the antenna sampling grid)
  • The width is that of the main lobe, searched outwards from the maximum; side lobes above the threshold are not included
  • Azimuth: cut at the elevation of the maximum, circular across ±180° when the grid covers the full circle; 360° when the whole cut is above the threshold (e.g. a beam pointing to a pole)
  • Elevation: cut along the great circle through the maximum, so a lobe can extend across the poles; at most 180°
  • Calculated per element, not per port; ignores element coupling
  • Accepts both single-frequency (3D pattern fields) and multi-frequency (4D pattern fields) arrayant dicts; output dimensionality follows the input
Usage:
bw_az, bw_el, az_pt, el_pt = quadriga_lib.arrayant.calc_beamwidth( arrayant )
bw_az, bw_el, az_pt, el_pt = quadriga_lib.arrayant.calc_beamwidth( arrayant, element, threshold_dB )
Inputs:
  • arrayant — Arrayant dict; single-frequency or multi-frequency (4th pattern dim is frequency); only e_theta_re, e_theta_im, e_phi_re, e_phi_im, azimuth_grid, elevation_grid are used; see generate for the field layout
  • element — Element indices; if None or empty, all elements are used; (n_out,) or None; default: None
  • threshold_dB — Threshold in dB (3 = FWHM); default: 3.0
Outputs:
  • bw_az — Azimuth beamwidth in degrees; (n_out,) for single-frequency input, (n_out, n_freq) for multi-frequency input; n_out = n_elements when element is None
  • bw_el — Elevation beamwidth in degrees; same shape as bw_az
  • az_pt — Azimuth pointing angle of the main beam in degrees; same shape as bw_az
  • el_pt — Elevation pointing angle of the main beam in degrees; same shape as bw_az
See also:
  • combine_pattern (apply element coupling before calculating beamwidth)
  • calc_directivity (directivity in dBi of array antenna elements)

calc_directivity
Calculates the directivity in dBi of array antenna elements
  • Directivity = 10·log10(peak radiation intensity / mean over 4π); isotropic radiator = 0 dBi
  • Calculated per element, not per port; ignores element coupling
  • Independent of the scale of the pattern; an element whose pattern is zero everywhere gives 0 dBi
  • Accepts both single-frequency (3D pattern fields) and multi-frequency (4D pattern fields) arrayant dicts; output dimensionality follows the input
Usage:
directivity = quadriga_lib.arrayant.calc_directivity( arrayant )
directivity = quadriga_lib.arrayant.calc_directivity( arrayant, element )
Inputs:
  • arrayant — Arrayant dict; single-frequency or multi-frequency (4th pattern dim is frequency); only e_theta_re, e_theta_im, e_phi_re, e_phi_im, azimuth_grid, elevation_grid are used; see generate for the field layout
  • element — Element indices; if None or empty, all elements are used; (n_out,) or None; default: None
Outputs:
  • directivity — Directivity in dBi; (n_out,) for a single-frequency input, (n_out, n_freq) for a multi-frequency input; n_out = n_elements when element is None
See also:
  • combine_pattern (apply element coupling before calculating directivity)
  • calc_beamwidth (calculates the beam width of array antennas)

combine_pattern
Combine element patterns, positions, and coupling weights into effective radiation patterns
  • Integrates the element field patterns, element positions, and coupling weights into one effective pattern per port (column of the coupling matrix)
  • The result behaves as a virtual array with one element per port, zeroed element positions, and an identity coupling matrix
  • Speeds up MIMO channel computation; useful for beamforming in 5G systems and network planning
  • Accepts a frequency-dependent antenna (4D pattern fields); the pattern is then combined per frequency
  • freq may recompute (interpolate) the combined pattern at one or more requested frequencies
  • The element positions add a phase that depends on frequency and propagation_speed; the default speed of light applies to radio waves, use about 343 m/s for acoustic arrays (e.g. from generate_speaker)
Usage:
# Single frequency
arrayant_out = quadriga_lib.arrayant.combine_pattern( arrayant )
arrayant_out = quadriga_lib.arrayant.combine_pattern( arrayant, freq, azimuth_grid, elevation_grid )

# Multiple frequencies (freq as a 1D array, or a frequency-dependent input antenna)
arrayant_out = quadriga_lib.arrayant.combine_pattern( arrayant, freq, azimuth_grid, elevation_grid )

# Acoustic array (speed of sound)
arrayant_out = quadriga_lib.arrayant.combine_pattern( arrayant, propagation_speed=343.0 )
Inputs:
  • arrayant — Dict with the array antenna data; keys as documented in generate; 4D pattern fields require center_freq with one value per frequency entry (n_freq,)
  • freq — Alternative center frequency in Hz; scalar or 1D array; if given, the pattern is recomputed at each value; if None, each input entry's center_freq is used; a scalar <= 0 is treated as not given; default: None
  • azimuth_grid — Alternative output azimuth grid in rad; -pi to pi; sorted; (n_azimuth_out,); if None, the input grid is used; default: None
  • elevation_grid — Alternative output elevation grid in rad; -pi/2 to pi/2; sorted; (n_elevation_out,); if None, the input grid is used; default: None
  • propagation_speed — Wave propagation speed in m/s; positive and finite; use about 343 for acoustics; default: 299792458.0
Outputs:
  • arrayant_out — Dict with the combined array antenna data; keys as in generate
See also:
  • generate (for field layout in the arrayant struct)
  • rotate_pattern (for changing the orientation of elements before combining)
  • calc_beamwidth (calculates the beam width of array antennas)
  • calc_directivity (directivity in dBi of array antenna elements)

concat
Concatenate two array antennas into a single one
  • Appends all elements of arrayant2 onto arrayant1 along the element dimension; the element_pos matrices are joined horizontally
  • Both inputs must share identical azimuth and elevation sampling grids
  • Coupling is assembled block-diagonally: arrayant1's elements connect only to its own ports, arrayant2's elements only to its own ports
  • center_freq and name are taken from arrayant1
  • Frequency-dependent input (4D pattern fields): both inputs must have the same number of frequency entries with matching center_freq at each index; concatenation is done per entry
  • Output format matches the input: single-frequency dict for 3D input, frequency-dependent dict for 4D input
Usage:
arrayant_out = quadriga_lib.arrayant.concat( arrayant1, arrayant2 )
Inputs:
  • arrayant1 — Dict with the first array antenna; keys as in generate; pattern fields may be 3D (n_elevation, n_azimuth, n_elements) or 4D (n_elevation, n_azimuth, n_elements, n_freq)
  • arrayant2 — Dict with the second array antenna; must use the same azimuth and elevation grids as arrayant1, and for 4D input the same number of frequency entries with matching center_freq
Outputs:
  • arrayant_out — Dict with the concatenated array antenna; same keys and layout as the inputs; single-frequency dict for 3D input, frequency-dependent dict for 4D input

copy_element
Create copies of array antenna elements
  • Copies a source element to one or more destination slots within an arrayant
  • The antenna is resized when a destination index exceeds the current number of elements
  • Coupling-matrix entries for newly added elements are set to identity; existing coupling is kept
  • Works on single-frequency dicts (3D pattern fields) and frequency-dependent dicts (4D pattern fields); the same copy is applied to every frequency and a matching dict is returned
  • If source_element has one entry, that element is copied to every index in dest_element
  • If source_element has several entries, dest_element must have the same length and copies are performed pairwise as source_element[i] to dest_element[i]
Usage:
# Copy element 0 to position 1
arrayant_out = quadriga_lib.arrayant.copy_element( arrayant, 0, 1 )

# Copy element 0 to several positions
arrayant_out = quadriga_lib.arrayant.copy_element( arrayant, 0, [2, 3] )

# Pairwise copy — source_element and dest_element must have equal length
arrayant_out = quadriga_lib.arrayant.copy_element( arrayant, [0, 1], [2, 3] )
Inputs:
  • arrayant — Dict with the array antenna data; keys as in generate; pattern fields may be 3D (n_elevation, n_azimuth, n_elements) or 4D (n_elevation, n_azimuth, n_elements, n_freq)
  • source_element — Index of the source element(s); scalar int or 1D list or array of int; (n_copy,)
  • dest_element — Index of the destination element(s); scalar int 1D list or array of int; (n_copy,); must have the same length as source_element unless source_element is a single index
Outputs:
  • arrayant_out — Dict with the modified array antenna data; same keys and layout as arrayant; single-frequency dict for 3D input, frequency-dependent dict for 4D input

export_obj_file
Export antenna pattern geometry to a Wavefront OBJ file for 3D visualization
  • The pattern is mapped onto an icosphere; a higher icosphere_n_div gives a finer mesh
  • The OBJ file is written to fn; the function returns nothing
  • Accepts a frequency-dependent antenna (4D pattern fields); freq_ind selects which frequency entry is exported
Usage:
quadriga_lib.arrayant.export_obj_file( fn, arrayant, directivity_range, colormap, object_radius, \
    icosphere_n_div, element, freq_ind )
Inputs:
  • fn — Output OBJ filename; str; must not be empty and must end in .obj
  • arrayant — Dict with the array antenna data; keys as in generate; pattern fields may be 3D (n_elevation, n_azimuth, n_elements) or 4D (n_elevation, n_azimuth, n_elements, n_freq)
  • directivity_range — Dynamic range of the visualized directivity pattern in dB; default: 30.0
  • colormap — Colormap name; default: jet; Available: jet, parula, winter, hot, turbo, copper, spring, cool, gray, autumn, summer
  • object_radius — Radius of the exported object in meters; default: 1.0
  • icosphere_n_div — Icosphere subdivision count; higher gives a finer mesh; see icosphere; default: 4
  • element — Element indices to export; 1D list or array of int; None or empty exports all elements; default: None
  • freq_ind — Frequency index to export from a frequency-dependent antenna; must satisfy 0 <= freq_ind &lt; n_freq; default: 0

generate
Generates predefined array antenna models
  • Dispatches to one of several C++ generator functions based on the type string
  • Supported types: omni, dipole (or short-dipole), half-wave-dipole, xpol, custom, ula, 3gpp (or 3GPP), multibeam
  • All arguments after type are keyword-only and type-specific; defaults are filled where omitted
  • For 3gpp and ula, a pattern dict can override the default per-element pattern
  • multibeam combines beams via MRT weighting; set separate_beams=True for one beam per direction
Usage:
# Simple antennas (v-pol)
ant = quadriga_lib.arrayant.generate('omni')
ant = quadriga_lib.arrayant.generate('dipole')
ant = quadriga_lib.arrayant.generate('half-wave-dipole')

# Cross-polarized isotropic
ant = quadriga_lib.arrayant.generate('xpol')

# Custom 3dB beamwidth
ant = quadriga_lib.arrayant.generate('custom', az_3dB=90.0, el_3dB=90.0, rear_gain_lin=0.0)

# Uniform linear array
ant = quadriga_lib.arrayant.generate('ula', N=4, freq=2.4e9, spacing=0.7, pol=1)

# 3GPP-NR array (default 3GPP element pattern)
ant = quadriga_lib.arrayant.generate('3gpp', M=2, N=2, freq=3.7e9, pol=1, spacing=0.7)

# 3GPP-NR array with custom per-element pattern dict
ant = quadriga_lib.arrayant.generate('3gpp', M=2, N=2, freq=3.7e9, pol=1, pattern=my_pattern)

# Multi-beam M×N array
ant = quadriga_lib.arrayant.generate('multibeam', M=6, N=6, freq=3.7e9, pol=1, \
    beam_az=[-30.0, 30.0], beam_el=[0.0, 0.0], separate_beams=False)
Inputs (common):
  • type — Antenna model type; str
  • res — Pattern sampling grid resolution in degrees; default: 10 for omni and xpol, 1 otherwise
  • freq — Center frequency in Hz; default: 299792458 (λ = 1 m)
Inputs (custom, 3gpp, multibeam):
  • az_3dB — Azimuth 3dB beamwidth in degrees; default: 90 for custom, 67 for 3gpp, 120 for multibeam
  • el_3dB — Elevation 3dB beamwidth in degrees; same defaults as az_3dB
  • rear_gain_lin — Back-to-front gain ratio (linear scale); default: 0.0
Inputs (ula, 3gpp, multibeam):
  • M — Number of vertical elements per panel; default: 1; ignored for ula
  • N — Number of horizontal elements per panel; default: 1
  • pol — Polarization mode (1..6); default: 1

    pol Description
    1 Vertical polarization
    2 H/V polarization (2NM elements)
    3 ±45° polarization (2NM elements)
    4 Vertical, vertical elements combined (N elements)
    5 H/V, vertical elements combined (2N elements)
    6 ±45°, vertical elements combined (2N elements)
  • spacing — Inter-element spacing in wavelengths; default: 0.5
Inputs (3gpp only):
  • tilt — Electrical downtilt in degrees; applies to pol = 4/5/6; default: 0.0
  • Mg — Number of vertically stacked panels; default: 1
  • Ng — Number of horizontally stacked panels; default: 1
  • dgv — Panel spacing in vertical direction in wavelengths; default: 0.5
  • dgh — Panel spacing in horizontal direction in wavelengths; default: 0.5
Inputs (ula, 3gpp):
  • pattern — Custom per-element pattern dict (same field layout as the output); overrides default 3GPP/ULA element pattern; only the radiation pattern is used: element positions, coupling and center frequency of the pattern are ignored; default: empty dict (use built-in pattern)
Inputs (multibeam only):
  • beam_az — Azimuth beam angles in degrees; (n_beams,); default: [0.0]
  • beam_el — Elevation beam angles in degrees; (n_beams,); default: [0.0]
  • beam_weight — Per-beam scaling factor; not normalized; same length as beam_az; default: [1.0, 1.0, ...] (all-ones)
  • separate_beams — Produce one independent beam per angle pair (weights ignored); default: False
  • apply_weights — Apply the beamforming weights to the output coupling matrix; default: False
Outputs:
  • ant — Dict with fields:

    Field Description Size
    e_theta_re e-theta field component, real part [n_elevation, n_azimuth, n_elements]
    e_theta_im e-theta field component, imaginary part [n_elevation, n_azimuth, n_elements]
    e_phi_re e-phi field component, real part [n_elevation, n_azimuth, n_elements]
    e_phi_im e-phi field component, imaginary part [n_elevation, n_azimuth, n_elements]
    azimuth_grid Azimuth angles in rad, -π to π, sorted [n_azimuth]
    elevation_grid Elevation angles in rad, -π/2 to π/2, sorted [n_elevation]
    element_pos Element (x,y,z) positions in meters [3, n_elements]
    coupling_re Coupling matrix, real part [n_elements, n_ports]
    coupling_im Coupling matrix, imaginary part [n_elements, n_ports]
    center_freq Center frequency in Hz; inputs accept (1,) scalar
    name Name of the array antenna object string

generate_speaker
Generate a parametric frequency-dependent loudspeaker directivity model
  • Returns a multi-frequency arrayant dict; pattern fields are 4D arrays where the 4th dim is frequency; for a single frequency the dict is a single-frequency arrayant dict (3D pattern fields, scalar center_freq)
  • Directivity is stored as real-valued data in e_theta_re; dipole rear hemisphere is encoded with negative sign for 180° phase inversion
  • Multi-driver systems (e.g. two-way) are built by calling this per driver and combining via arrayant.concat; crossover behavior emerges from overlapping bandpass responses
  • Frequency response is a Butterworth-style bandpass: H(f) = 1/sqrt(1+(f_low/f)^(2n)) · 1/sqrt(1+(f/f_high)^(2n)), where n = slope_dB_per_octave / 6; -3 dB at the cutoff frequencies
  • Sensitivity scales amplitude linearly relative to 85 dB SPL: sens_lin = 10^((sensitivity - 85) / 20)
  • If frequencies is None or empty, third-octave band centers are auto-generated from one band below lower_cutoff to one band above upper_cutoff, clipped to 20-20000 Hz
  • Speed of sound assumed to be 343 m/s
  • Driver models (driver_type):
    • piston - circular piston in baffle, D(theta) = 2·J1(ka·sin theta)/(ka·sin theta), rotationally symmetric, narrows with increasing ka
    • horn - separable cosine-power cos^n(angle) with frequency-dependent blend toward omni below horn_control_freq
    • omni - frequency-independent omnidirectional pattern
  • Enclosure models (radiation_type):
    • monopole - no modification
    • hemisphere - sealed box with baffle-step transition, f_baffle = c/(pi·sqrt(W·H))
    • dipole - figure-8, R = abs(cos(theta_off)) with sign inversion in rear hemisphere
    • cardioid - R = 0.5·(1+cos(theta_off))
  • For horn, if horn_control_freq = 0, it is auto-derived as f_ctrl = c/(2pi·radius)
Usage:
# Default piston driver (4-inch, 80 Hz – 12 kHz)
speaker = quadriga_lib.arrayant.generate_speaker()

# Horn tweeter with custom coverage
speaker = quadriga_lib.arrayant.generate_speaker(driver_type='horn', radius=0.025, \
    lower_cutoff=1500.0, upper_cutoff=20000.0, hor_coverage=90.0, ver_coverage=60.0)

# Omnidirectional subwoofer with steep rolloff
speaker = quadriga_lib.arrayant.generate_speaker(driver_type='omni', radius=0.165, \
    lower_cutoff=30.0, upper_cutoff=300.0, lower_rolloff_slope=24.0, upper_rolloff_slope=24.0, \
    sensitivity=90.0, radiation_type='monopole')

# Piston driver at specific frequencies
speaker = quadriga_lib.arrayant.generate_speaker( frequencies=np.array([100.0, 500.0, 1000.0, 5000.0, 10000.0]), \
    angular_resolution=5.0)
Inputs:
  • driver_type — Driver directivity model: piston, horn, or omni; default: piston
  • radius — Effective radiating radius in m; cone/dome radius for piston, mouth radius for horn; default: 0.05
  • lower_cutoff — Lower -3 dB bandpass frequency in Hz; default: 80
  • upper_cutoff — Upper -3 dB bandpass frequency in Hz; default: 12000
  • lower_rolloff_slope — Low-frequency rolloff in dB/octave (12 dB/oct = 2nd-order Butterworth); default: 12
  • upper_rolloff_slope — High-frequency rolloff in dB/octave; default: 12
  • sensitivity — On-axis sensitivity in dB SPL at 1W/1m; 85 dB gives unity amplitude; default: 85
  • radiation_type — Enclosure radiation model: monopole, hemisphere, dipole, or cardioid; default: hemisphere
  • hor_coverage — Horn horizontal coverage angle in degrees; 0 auto-defaults to 90; horn only; default: 0
  • ver_coverage — Horn vertical coverage angle in degrees; 0 auto-defaults to 60; horn only; default: 0
  • horn_control_freq — Horn pattern control frequency in Hz; 0 auto-derives from radius; default: 0
  • baffle_width — Baffle width in m; used by hemisphere model; default: 0.15
  • baffle_height — Baffle height in m; used by hemisphere model; default: 0.25
  • frequencies — Frequency sample points in Hz; auto-generated third-octave bands if None; (n_freq,) or None; default: None
  • angular_resolution — Azimuth and elevation grid resolution in degrees; default: 5
Outputs:
  • speaker — Multi-frequency arrayant dict with the fields below; for n_freq = 1 the pattern fields are 3D (n_elevation, n_azimuth, n_elements) and center_freq is a float:
    • e_theta_re — e-theta field component, real part; (n_elevation, n_azimuth, n_elements, n_freq)
    • e_theta_im — e-theta field component, imaginary part; (n_elevation, n_azimuth, n_elements, n_freq)
    • e_phi_re — e-phi field component, real part; (n_elevation, n_azimuth, n_elements, n_freq)
    • e_phi_im — e-phi field component, imaginary part; (n_elevation, n_azimuth, n_elements, n_freq)
    • azimuth_grid — Azimuth angles in rad, -π to π, sorted; (n_azimuth,)
    • elevation_grid — Elevation angles in rad, -π/2 to π/2, sorted; (n_elevation,)
    • element_pos — Element (x,y,z) positions in meters; (3, n_elements)
    • coupling_re — Coupling matrix, real part; (n_elements, n_ports) or (n_elements, n_ports, n_freq) if it varies across frequencies
    • coupling_im — Coupling matrix, imaginary part; (n_elements, n_ports) or (n_elements, n_ports, n_freq) if it varies across frequencies
    • center_freq — Frequency samples in Hz; (n_freq,)
    • name — Name of the array antenna object; str

interpolate
Interpolate polarimetric array antenna field patterns (single- and multi-frequency)
  • Interpolates the complex e-theta (V) and e-phi (H) field components at the requested azimuth / elevation angles
  • NaN or infinite angles give NaN in all outputs for that angle (and element); no error is raised
  • Single-frequency input (3D pattern fields) returns 2D outputs (n_out, n_ang); the optional dist and local_angles outputs are available only on this path
  • Multi-frequency input (4D pattern fields) interpolates spatially and across frequency; for each target frequency the two bracketing center_freq entries are blended via SLERP
  • Passing frequency adds a frequency dimension to the output (n_out, n_ang, n_freq_out); for a single-frequency antenna the spatial result is simply replicated across the requested frequencies
  • azimuth / elevation of shape (1, n_ang) apply the same angles to all elements (planar wave); shape (n_out, n_ang) gives per-element angles (spherical wave)
Usage:
# Single-frequency, separate real / imaginary parts
vr, vi, hr, hi = quadriga_lib.arrayant.interpolate( arrayant, azimuth, elevation )

# Complex-valued output
v, h = quadriga_lib.arrayant.interpolate( arrayant, azimuth, elevation, complex=True )

# Projected distance / local angles (single-frequency only)
vr, vi, hr, hi, dist = quadriga_lib.arrayant.interpolate( arrayant, azimuth, elevation, dist=True )
vr, vi, hr, hi, azimuth_loc, elevation_loc, gamma = quadriga_lib.arrayant.interpolate( arrayant, azimuth, \
    elevation, orientation=ori, local_angles=True )

# Element selection, orientation, element positions
vr, vi, hr, hi = quadriga_lib.arrayant.interpolate( arrayant, azimuth, elevation, element, orientation, element_pos )

# Multi-frequency interpolation — output gains a frequency axis
vr, vi, hr, hi = quadriga_lib.arrayant.interpolate( arrayant, azimuth, elevation, frequency=freqs )
Inputs:
  • arrayant — Dict with the array antenna data; keys as in generate; pattern fields may be 3D (n_elevation, n_azimuth, n_elements) or 4D (n_elevation, n_azimuth, n_elements, n_freq); 4D input requires center_freq with one value per frequency entry (n_freq,)
  • azimuth — Azimuth angles in rad, in [-pi, pi]; (1, n_ang) for shared angles (planar wave) or (n_out, n_ang) for per-element angles (spherical wave)
  • elevation — Elevation angles in rad, in [-pi/2, pi/2]; same shape as azimuth
  • element — Element indices to interpolate; duplicates allowed; (n_out,) or a list of int; None or empty uses all elements (n_out = n_elements); default: None
  • orientation — antenna orientation (bank, tilt, heading) in rad; shape (3, 1), (3, n_out), (3, 1, n_ang), or (3, n_out, n_ang); None uses East-facing broadside; default: None
  • element_pos — Alternative element (x,y,z) positions in m; (3, n_out); None falls back to arrayant["element_pos"] (or zeros); default: None
  • frequency — Target frequencies in Hz; (n_freq_out,) or scalar; adds a frequency axis to the output; for 4D input it interpolates between entries, for 3D input it replicates the spatial result; if omitted for 4D input the entries' center_freq values are used; default: None
  • complex — If True, return complex-valued arrays instead of separate real / imaginary parts; default: False
  • dist — If True, also return the projected distances; single-frequency input only and not allowed together with frequency; default: False
  • local_angles — If True, also return the antenna-local angles; single-frequency input only and not allowed together with frequency; default: False
  • fast_access — If True, require the pattern arrays to be double and column-major (Fortran-contiguous) so they can be read without a copy; raises if not. With False, such arrays are read without a copy as well and all others are copied; default: False
Outputs:
Returned as a tuple; its length depends on complex, dist, and local_angles.
  • vr, vi, hr, hi — Real / imaginary parts of the interpolated e-theta (V) and e-phi (H) field components; (n_out, n_ang), or (n_out, n_ang, n_freq_out) when frequency is given; returned when complex is False
  • v, h — Complex-valued e-theta (V) and e-phi (H) components; same shape as above; returned instead of vr, vi, hr, hi when complex is True
  • dist — Projected distances between elements on the wavefront plane, used for phase computation; (n_out, n_ang); returned only when dist is True
  • azimuth_loc, elevation_loc, gamma — Azimuth, elevation, and polarization rotation angles in the local element frame, in rad; (n_out, n_ang) each; returned only when local_angles is True
See also:
  • qdant_read / qdant_write (load / save arrayant data)
  • generate (arrayant struct layout)
  • generate_speaker (typical multi-frequency struct array source)

qdant_read
Reads array antenna data from QDANT files
  • QDANT is the QuaDRiGa array antenna exchange format, an XML format for storing antenna patterns
  • A QDANT file may hold one or several entries (e.g. a frequency-dependent antenna model)
  • id reads a single entry by its 1-based ID; the result is a dict with 3D pattern fields
  • id = 0 reads every entry: a frequency-dependent dict with 4D pattern fields when the file holds multiple entries, or a plain single-entry dict (3D fields) when it holds exactly one; multiple entries must form a frequency set (same number of elements, same azimuth and elevation grids, element positions and coupling size), otherwise an error asks to pass id
  • Differs from MATLAB, where arrayant_qdant_read(fn) without id reads every entry (here: id = 0)
  • Reading all entries is the inverse of qdant_write with a 4D-pattern dict
  • An id that is not in the file raises an error; the first entry counts as ID 1 only if it has no id attribute
  • Malformed files raise an error, also when they declare more elements (NoElements) than the file has data for; elements without pattern data read as zeros (at most 2^24 zero values per entry)
Usage:
# Read a single entry (default: ID 1)
data = quadriga_lib.arrayant.qdant_read( fn )
data = quadriga_lib.arrayant.qdant_read( fn, id )

# Read every entry as a frequency-dependent arrayant
data = quadriga_lib.arrayant.qdant_read( fn, id=0 )
Inputs:
  • fn — path to the QDANT file; str; must not be empty
  • id — 1-based ID of the entry to read; 0 reads all entries (see above); default: 1
Outputs:
  • data — Dict with the array antenna data; keys as in generate, with these specifics:
    • e_theta_re, e_theta_im, e_phi_re, e_phi_im — Pattern fields; (n_elevation, n_azimuth, n_elements) for a single entry, or (n_elevation, n_azimuth, n_elements, n_freq) when id = 0 reads multiple entries
    • center_freq — Center frequency in Hz; scalar for a single entry, (n_freq,) when reading multiple entries
    • coupling_re, coupling_im — Coupling matrices; (n_elements, n_ports), or (n_elements, n_ports, n_freq) when reading multiple entries with per-entry coupling
    • layout — Matrix of element IDs describing how the entries are arranged in the file; int64
See also:
  • qdant_write (for writing QDANT data)
  • generate (for the arrayant struct layout)
  • QuaDRiGa Array Antenna Exchange Format (QDANT)

qdant_write
Writes array antenna data to QDANT files
  • QDANT is the QuaDRiGa array antenna exchange format, an XML format for storing antenna patterns
  • Single-frequency input (3D pattern fields) writes one entry; id places it in the file, and several antennas can share one file via distinct IDs
  • Frequency-dependent input (4D pattern fields) writes every frequency entry with sequential 1-based IDs; id and layout do not apply, and the file must not already exist
  • Returns the ID assigned to the written entry (0 for a frequency-dependent write)
  • Without layout, the layout in the file is replaced by a row of all IDs in the file in file order; a custom layout written before is lost (pass it again with every write that should keep it)
  • The file has single-precision-equivalent accuracy relative to the element peak: pattern magnitudes (dB) and phases (degree) are rounded so that every sample is within 6e-8 of the peak amplitude of its element; samples far below the peak are less accurate relative to their own amplitude (about 6e-4 at -80 dB, 6e-2 at -120 dB below the peak); positions and coupling are written as float values (at most 9 significant digits); sampling grids are rounded to 0.001 degree; all non-zero pattern samples are written at any level, exact zeros as -inf dB
Usage:
# Single-frequency write
id_in_file = quadriga_lib.arrayant.qdant_write( fn, arrayant )
id_in_file = quadriga_lib.arrayant.qdant_write( fn, arrayant, id )

# Frequency-dependent write (4D patterns) — all entries written sequentially
arrayant.quadriga_lib.qdant_write( fn, arrayant )
Inputs:
  • fn — Output QDANT filename; str; must not be empty
  • arrayant — Dict with the array antenna data; keys as in generate; pattern fields may be 3D (n_elevation, n_azimuth, n_elements) or 4D (n_elevation, n_azimuth, n_elements, n_freq); 4D input requires center_freq with one value per frequency entry (n_freq,)
  • id — Target 1-based ID of the entry inside the file; 0 appends after the highest existing ID (or 1 if the file does not exist); ignored for 4D input; default: 0
  • layout — uint32 matrix organizing multiple antenna IDs within the file; must reference only IDs present in the file; ignored for 4D input; default: None (a row of all IDs in the file, which replaces a layout written before)
Outputs:
  • id_in_file — ID assigned to the entry in the file after writing; 0 for a frequency-dependent (4D) write
See also:
  • qdant_read (for reading QDANT data)
  • generate (for the arrayant struct layout)
  • QuaDRiGa Array Antenna Exchange Format (QDANT)

rotate_pattern
Rotate antenna radiation patterns around the principal axes using Euler rotations
  • Rotates the pattern and/or polarization of array antenna elements around the x (bank), y (tilt), and z (heading) axes
  • Rotations are applied in the order x, y, z, composed as Rz·Ry·Rx (intrinsic Tait-Bryan)
  • Single-frequency input (3D pattern fields): usage 0 and 1 adjust the sampling grid for non-uniformly sampled antennas
  • Coupling, center_freq and name are kept, also when the sampling grid is adjusted
  • Frequency-dependent input (4D pattern fields): the rotation is applied to every entry and the grid is never adjusted, since all entries must share one grid
  • For scalar acoustic fields (pressure stored in e_theta_re only) use usage = 1 to avoid spurious polarization effects
Usage:
# Rotate all elements by 45 deg bank
arrayant_out = quadriga_lib.arrayant.rotate_pattern( arrayant, x_deg=45.0 )

# Rotate only elements 0 and 1 by 90 deg heading
arrayant_out = quadriga_lib.arrayant.rotate_pattern( arrayant, z_deg=90.0, element=[0, 1] )

# Frequency-dependent input (4D patterns) — same interface
arrayant_out = quadriga_lib.arrayant.rotate_pattern( arrayant, y_deg=10.0 )
Inputs:
  • arrayant — Dict with the array antenna data; keys as in generate; pattern fields may be 3D (n_elevation, n_azimuth, n_elements) or 4D (n_elevation, n_azimuth, n_elements, n_freq)
  • x_deg — Rotation around the x-axis (bank) in degrees; default: 0.0
  • y_deg — Rotation around the y-axis (tilt) in degrees; default: 0.0
  • z_deg — Rotation around the z-axis (heading) in degrees; default: 0.0
  • usage — Rotation mode; default: 0

    Mode Pattern Polarization Grid adj.
    0 Yes Yes Yes
    1 Yes No Yes
    2 No Yes No
    3 Yes Yes No
    4 Yes No No
    for 4D input the grid is never adjusted, so 0/3 and 1/4 are equivalent
  • element — Element indices to rotate; 1D list or array of int; None or empty rotates all elements; default: None
Outputs:
  • arrayant_out — Dict with the rotated array antenna data; same keys and layout as arrayant; single-frequency dict for 3D input, frequency-dependent dict for 4D input


Channel functions


baseband_freq_response
Compute the baseband frequency response of a MIMO channel
  • Transforms time-domain channel coefficients into the frequency-domain transfer function H(f)
  • Snapshots are passed as Python lists; each list item is one snapshot, processed in parallel via OpenMP
  • Two per-snapshot modes, selected by the ndim of the coefficient arrays:
    • single-freq: 3D items (n_rx, n_tx, n_path); DFT over path delays at the requested carriers (AVX2)
    • multi-freq: 4D items (n_rx, n_tx, n_path, n_freq_in); SLERP interpolation across freq_in, then delay-induced phase applied per output carrier
  • All list items must share ndim, n_rx, n_tx (and n_freq_in for 4D); n_path may vary per snapshot
  • Coefficients are given either as one complex array coeff, or as split coeff_re + coeff_im; supplying both forms is an error
  • Output carriers are defined one of two mutually exclusive ways:
    • bandwidth paired with pilot_grid (or carriers for an evenly spaced grid) — single-freq only
    • freq_in + freq_out as absolute frequencies — required for multi-freq, optional for single-freq
  • For single-freq with freq_in + freq_out, the baseband grid is derived internally; the phase is referenced to freq_in[0] when given, else to min(freq_out)
  • delay may be broadcast: a (1, 1, n_path) item applies the same delays to every RX/TX pair; for multi-freq a 3D delay item is reused for all input frequencies
  • snap selects a 0-based subset of snapshots; omitted processes all snapshots
  • single-freq: the phase bandwidth · pilot_grid · delay (in cycles) is computed in double precision and reduced to one period before sin / cos are evaluated in single precision; coefficients and sums are single precision, double inputs are narrowed to float, results widened back; multi-freq computes in double precision
Usage:
# Single-freq, bandwidth + evenly spaced carriers
hmat = quadriga_lib.channel.baseband_freq_response( coeff=coeff, delay=delay, bandwidth=100e6, carriers=128 )

# Single-freq, absolute frequencies
hmat = quadriga_lib.channel.baseband_freq_response( coeff=coeff, delay=delay, freq_in=freq_in, freq_out=freq_out )

# Multi-freq, split real / imaginary parts
hmat = quadriga_lib.channel.baseband_freq_response( coeff_re=cre, coeff_im=cim, delay=delay, freq_in=freq_in, freq_out=freq_out )
Inputs:
  • coeff — Complex channel coefficients; list of length n_snap; each item (n_rx, n_tx, n_path) (single-freq) or (n_rx, n_tx, n_path, n_freq_in) (multi-freq); mutually exclusive with coeff_re / coeff_im; default: None
  • delay — Path delays in seconds; list of length n_snap; each item shaped like the matching coeff item or broadcast as (1, 1, n_path) (with an optional 4th dimension n_freq_in)
  • bandwidth — Baseband bandwidth in Hz; paired with pilot_grid or carriers; single-freq only; cannot be combined with freq_out; default: 0.0
  • carriers — Number of evenly spaced carriers on [0, 1]; used only when both pilot_grid and freq_out are omitted; default: 128
  • pilot_grid — Normalized sub-carrier positions, 0.0 = center, 1.0 = center + bandwidth; 1D array of length n_carrier; default: None
  • snap — 0-based snapshot indices to process; 1D array of length n_out; omitted processes all snapshots; default: None
  • coeff_re — Real part of channel coefficients; same list/shape layout as coeff; must be paired with coeff_im; mutually exclusive with coeff; default: None
  • coeff_im — Imaginary part of channel coefficients; same layout as coeff_re; default: None
  • freq_in — Input sample frequencies in Hz; 1D array; required for multi-freq input; for single-freq input used together with freq_out as the phase reference; default: None
  • freq_out — Absolute output carrier frequencies in Hz; 1D array of length n_carrier; required for multi-freq input; may replace bandwidth + pilot_grid for single-freq; default: None
  • remove_delay_phase — If True, undo the delay-induced phase baked in by the channel generator before SLERP, then re-apply it analytically per output carrier; multi-freq only; needs channels generated with use_absolute_delays = True: the coefficients of get_channels_* carry the phase of the absolute path length also when delay is relative, and with relative delays the phase of the TX-RX distance is interpolated across freq_in, which gives wrong phases (magnitudes stay right); default: True
Outputs:
  • hmat — Complex frequency-domain channel matrix; shape (n_rx, n_tx, n_carrier, n_out), where n_out is the number of processed snapshots
See also:
  • get_channels_spherical (single-frequency channel generator)
  • get_channels_multifreq (multi-frequency channel generator)

quantize_delays
Map path delays to a fixed tap grid using two-tap power-weighted interpolation
  • Each path delay is approximated by two adjacent taps with coefficients scaled by (1−δ)^α and δ^α, where δ is the fractional offset within the bin and α is power_exponent
  • Two-tap interpolation avoids discontinuities when delays cross tap boundaries
  • Use power_exponent = 1.0 for narrowband (linear interpolation) or 0.5 for wideband (incoherent power preservation)
  • If all fractional per-tap offsets are below 0.01 or above 0.99, weight computation is skipped (nearest-neighbor selection) but tap-selection logic still applies
  • Snapshots are passed as Python lists; each list item is one snapshot and n_path may vary per item
  • Coefficients are given either as one complex list coeff, or as split coeff_re + coeff_im; supplying both forms is an error. The input and output forms are independent
  • complex=True returns one combined complex coefficient output; complex=False (default) returns separate real coeff_re_q and coeff_im_q
  • Input delay items may be per-antenna (n_rx, n_tx, n_path) or shared (1, 1, n_path); shared delays are expanded internally when fix_taps is 0 or 3
  • Output arrays are zero-padded along the tap dimension so that all snapshots share the same n_taps
  • Delays must be non-negative, as for a tapped delay line, with a tolerance of tap_spacing / 2: delays in (-tap_spacing / 2, 0) are treated as 0, so all of their power goes to tap 0. Delays at or below -tap_spacing / 2 raise ValueError, as do NaN, Inf and delays of 2^31 taps or more (delay / tap_spacing &lt; 2^31, e.g. 10.7 s at 5 ns or 12.4 h at 48 kHz)
  • Relative delays (use_absolute_delays = false in get_channels_spherical, get_channels_multifreq and get_channels_planar) are negative for element pairs that are closer to each other than the phase centres, by up to about (half the TX array size + half the RX array size) / propagation speed (both arrays endfire). They stay above -tap_spacing / 2 only while these half sizes add up to less than tap_spacing / 2 times the propagation speed: about 0.75 m for radio at 5 ns taps, but only about 3.6 mm for sound at 48 kHz taps, i.e. practically every acoustic array. In those cases use absolute delays (use_absolute_delays = true)
  • Run time and memory depend on the number of paths and taps, not on the absolute delay values
Usage:
# Split real / imaginary output
coeff_re_q, coeff_im_q, delay_q = quadriga_lib.channel.quantize_delays( coeff_re, coeff_im, delay )

# Complex input and / or output (keyword)
coeff_q, delay_q = quadriga_lib.channel.quantize_delays( coeff=coeff, delay=delay, complex=True )
Inputs:
  • coeff_re — Real part of channel coefficients; list of length n_snap; each item (n_rx, n_tx, n_path); must be paired with coeff_im; mutually exclusive with coeff; default: None
  • coeff_im — Imaginary part of channel coefficients; same layout as coeff_re; default: None
  • delay — Path delays in seconds; list of length n_snap; each item (n_rx, n_tx, n_path) or shared (1, 1, n_path); non-negative with a tolerance of tap_spacing / 2, finite, below 2^31 * tap_spacing
  • tap_spacing — Delay bin spacing in seconds, positive and finite; 5 ns corresponds to 200 MHz sampling rate; default: 5e-9
  • max_no_taps — Maximum number of output taps; 0 = unlimited; default: 48
  • power_exponent — Interpolation exponent α; default: 1.0
  • fix_taps — Delay grid sharing mode; 0 = per tx-rx pair and snapshot, 1 = single shared grid, 2 = per snapshot, 3 = per tx-rx pair across all snapshots; default: 0
  • stack — If True, stack snapshots into a 4D array; if False, return a list of per-snapshot arrays; default: False
  • complex — If True, return combined complex coefficients coeff_q; if False, return separate coeff_re_q and coeff_im_q; default: False
  • coeff — Complex channel coefficients; list of length n_snap; each item (n_rx, n_tx, n_path); mutually exclusive with coeff_re / coeff_im; default: None
Outputs:
  • coeff_q — Combined complex output coefficients; returned when complex is True; list of (n_rx, n_tx, n_taps) when stack is False, else (n_rx, n_tx, n_taps, n_snap)
  • coeff_re_q — Output coefficients, real part; returned when complex is False; list of (n_rx, n_tx, n_taps) when stack is False, else (n_rx, n_tx, n_taps, n_snap)
  • coeff_im_q — Output coefficients, imaginary part; returned when complex is False; same shape as coeff_re_q
  • delay_q — Output delays in seconds; list of (n_rx, n_tx, n_taps) or (1, 1, n_taps) when stack is False, else (n_rx, n_tx, n_taps, n_snap) or (1, 1, n_taps, n_snap); the (1, 1, ...) shape only for shared delay input with fix_taps 1 or 2

get_channels_multifreq
Compute channel coefficients for spherical waves across multiple frequencies
  • Multi-frequency extension of get_channels_spherical with frequency-dependent antenna patterns, path gains, and Jones matrices
  • Geometry (angles, element delays, LOS detection) is computed once and reused across all output frequencies
  • Aligns four frequency grids: TX array (ant_tx['center_freq']), RX array (ant_rx['center_freq']), input samples (freq_in), and output (freq_out)
  • Antenna pattern fields may be 3D (single-frequency, clamped for all output frequencies) or 4D (multi-frequency, 4th axis = frequency)
  • TX/RX patterns are interpolated per output frequency via SLERP with linear fallback
  • path_gain is interpolated linearly; M is interpolated via SLERP per complex entry pair to preserve phase
  • Coupling matrices are interpolated across frequencies (SLERP for complex pairs); pass 3D coupling (n_elem, n_ports, n_freq) for per-frequency coupling
  • Extrapolation clamps to the nearest frequency entry on all four grids
  • M accepts 8 rows (full polarimetric: the 2x2 Jones matrix (rows = RX polarisation V/H, columns = TX polarisation V/H), stored column-major with Re/Im interleaved: rows 0-1 = (V rx, V tx), rows 2-3 = (H rx, V tx), rows 4-5 = (V rx, H tx), rows 6-7 = (H rx, H tx)) or 2 rows (scalar pressure: Re, Im of the (V rx, V tx) entry only)
  • NLOS paths: the path length between the TX and RX phase centres is max(path_length, d_poly), where d_poly is the TX-FBS-LBS-RX polyline length; the length beyond the polyline (interactions between FBS and LBS) is added to the FBS-LBS segment. Delays and phases follow this length; the per-element offsets follow the FBS / LBS geometry
  • propagation_speed supports EM (speed of light, default) and acoustic (343 m/s) simulations
  • n_path_out = n_path + 1 if add_fake_los_path else n_path: with add_fake_los_path, slot 0 holds the LOS path (zero power if no LOS path was found; LOS = the path whose length is closest to the TX-RX distance, within 0.1 mm); a LOS path found in the input is moved to slot 0 and leaves a zero-power path in its original slot (input index + 1); all other paths keep their order, shifted by one slot
  • With 0 paths (all path inputs empty), the outputs are empty, (n_rx, n_tx, 0, n_freq_out); with add_fake_los_path = True they hold only this zero-power LOS path, with the LOS delays per antenna pair
  • If use_absolute_delays is false, the LOS delay between the TX and RX phase centres is subtracted from all paths; per-element delays can then be negative, down to about -(half the TX array size + half the RX array size) / propagation_speed (both arrays endfire). quantize_delays rejects delays at or below -tap_spacing / 2. For acoustics (propagation_speed about 343 m/s) that happens for practically every array: at 48 kHz taps, half sizes adding up to more than about 3.6 mm (a 5 cm microphone pair already exceeds it); for radio at 5 ns taps, about 0.75 m. Use use_absolute_delays = true in that case
  • The coefficients always carry the phase of the absolute path length, also when use_absolute_delays is false. baseband_freq_response with multi-frequency input and remove_delay_phase = True removes the phase of delay before it interpolates across freq_in, so it needs channels generated with use_absolute_delays = True; with relative delays, the phase of the TX-RX distance stays in the coefficients, is interpolated across the frequency grid and gives wrong phases
  • complex=True returns one combined complex coefficient array coeff; complex=False (default) returns separate real coeff_re and coeff_im via a zero-copy fast path
Usage:

    lbs_pos, path_gain, path_length, M, tx_pos, tx_orientation, rx_pos, rx_orientation, freq_in, \
    freq_out, use_absolute_delays, add_fake_los_path, propagation_speed )

Inputs:

  • ant_rx — RX arrayant dict; same format as ant_tx

  • lbs_pos — Last-bounce scatterer positions; (3, n_path)

  • path_length — Absolute TX-to-RX path lengths (between the phase centres); values shorter than the TX-FBS-LBS-RX polyline (e.g. 0) use the polyline length; (n_path,)

get_channels_planar
Calculate MIMO channel coefficients for planar wave paths
  • Computes complex channel coefficients and delays for all TX/RX port pairs across n_path propagation paths under the planar wave assumption.
  • Interpolates antenna patterns for both arrays, accounting for element positions, orientation, and polarization.
  • LOS path detection is distance-based; the input angles are not used for LOS detection.
  • Polarization coupling is applied via the 8-row transfer matrix M: the 2x2 Jones matrix (rows = RX polarisation V/H, columns = TX polarisation V/H), stored column-major with Re/Im interleaved: rows 0-1 = (V rx, V tx), rows 2-3 = (H rx, V tx), rows 4-5 = (V rx, H tx), rows 6-7 = (H rx, H tx).
  • path_length is used as given for the delay and phase of the phase centres (no geometry check).
  • Path data is given for n_freq frequencies; single-frequency data uses n_freq = 1.
  • The scalar argument freq selects the frequency index that is processed; a single frequency is returned per call.
  • If center_freq is None or the selected entry is 0, phase calculation is disabled and only delays are computed.
  • If use_absolute_delays == False, the straight-line TX-RX delay between the phase centres (LOS delay) is subtracted from all paths; per-element delays of pairs that are closer to each other than the phase centres are then negative, down to about -(half the TX array size + half the RX array size) / speed of light; quantize_delays rejects delays at or below -tap_spacing / 2 (at 5 ns taps: half sizes adding up to more than about 0.75 m), use use_absolute_delays = true in that case.
  • If add_fake_los_path == True, one output path is always added (output size n_path + 1): slot 0 holds the LOS path, with zero power if no LOS path was found. LOS = the strongest path whose path_length is within 0.1 mm of the TX-RX distance; it is moved to slot 0 and its original slot (input index + 1) holds a zero-power path. All other paths keep their order, shifted by one slot.
  • With 0 paths (all path inputs empty), the outputs are empty, (n_rx, n_tx, 0); with add_fake_los_path = True they hold only this zero-power LOS path, with the LOS delays per antenna pair.
  • complex=True returns one combined complex coefficient array coeff; complex=False (default) returns separate real coeff_re and coeff_im via a zero-copy fast path.

get_channels_spherical
Calculate MIMO channel coefficients and delays for spherical wave propagation
  • Computes complex channel coefficients and propagation delays for all TX/RX element pairs and paths, using the spherical wave assumption with per-element phase and delay.
  • Interpolates antenna patterns for both arrays, accounting for element positions and array orientation (bank/tilt/heading Euler angles).
  • Polarization coupling is applied via the 8-row transfer matrix M: the 2x2 Jones matrix (rows = RX polarisation V/H, columns = TX polarisation V/H), stored column-major with Re/Im interleaved: rows 0-1 = (V rx, V tx), rows 2-3 = (H rx, V tx), rows 4-5 = (V rx, H tx), rows 6-7 = (H rx, H tx).
  • NLOS paths: the path length between the TX and RX phase centres is max(path_length, d_poly), where d_poly is the TX-FBS-LBS-RX polyline length; the length beyond the polyline (interactions between FBS and LBS, e.g. paths of qrt_file_read with more than two interactions) is added to the FBS-LBS segment. Delays and phases follow this length; the per-element offsets follow the FBS / LBS geometry.
  • Path data is given for n_freq frequencies; single-frequency data uses n_freq = 1.
  • The scalar argument freq selects the frequency index that is processed; a single frequency is returned per call.
  • If center_freq is None or the selected entry is 0, phase calculation is disabled and only delays are computed.
  • If use_absolute_delays == False, the LOS delay between the TX and RX phase centres is subtracted from all paths. Delays are per element pair, so pairs that are closer to each other than the phase centres get negative delays, down to about -(half the TX array size + half the RX array size) / speed of light (both arrays endfire). quantize_delays maps delays above -tap_spacing / 2 to tap 0 and rejects lower ones (at 5 ns taps: half sizes adding up to more than about 0.75 m); use use_absolute_delays = true in that case.
  • LOS detection: the path whose length is closest to the TX-RX distance, within 0.1 mm.
  • If add_fake_los_path == True, one output path is always added (n_path + 1 outputs): slot 0 holds the LOS path, with zero power if no LOS path was found. If a LOS path was found, it is moved to slot 0 and its original slot (input index + 1) holds a zero-power path. All other paths keep their order, shifted by one slot.
  • With 0 paths (all path inputs empty), the outputs are empty, (n_rx, n_tx, 0); with add_fake_los_path = True they hold only this zero-power LOS path, with the LOS delays and angles per antenna pair (also per snapshot in batch mode).
  • complex=True returns one combined complex coefficient array coeff; complex=False (default) returns separate real coeff_re and coeff_im via a zero-copy fast path
Batch mode:
  • If fbs_pos is a list of arrays, the function switches to batch mode and processes n_out snapshots in one call, distributing the snapshots over all available cores (OpenMP).
  • The path inputs fbs_pos, lbs_pos, path_gain, path_length and M are then lists of length n_out, matching the output format of qrt_file_read; list entries that are Fortran-contiguous float64 arrays (as returned by qrt_file_read) are read in place, other entries are copied.
  • The position and orientation inputs are (3, n_out) arrays with one column per snapshot; a (3,) array or a single-column (3, 1) array is applied to all snapshots.
  • All outputs are returned as lists of length n_out, one entry per snapshot.
  • Snapshots without any path produce an empty output entry with n_path = 0, or only the zero-power LOS path when add_fake_los_path is set (as for a single snapshot).
  • Batch mode releases the GIL while processing, so it can be combined with Python threads. The function keeps references to all input arrays until it returns, but other threads must not write into them meanwhile.

get_ieee_indoor
Generate indoor MIMO channel realizations for IEEE TGn/TGac/TGax/TGah models
  • Generates one or multiple indoor channel realizations based on IEEE TGn/TGac/TGax/TGah model definitions
  • 2D model: azimuth angles and planar motion only, no elevation
  • Supported channel types: A, B, C, D, E, F (TGn definitions)
  • MU-MIMO supported (n_users > 1) with per-user distances/floors and optional angle offsets per TGac
  • Time-evolving channels via observation_time, update_rate, and mobility parameters; observation_time = 0.0 yields a static channel
  • Default KF (linear): A/B/C → 1 (LOS) / 0 (NLOS), D → 2/0, E/F → 4/0; applied to first tap only; breakpoint ignored when KF_linear >= 0
  • Default XPR NLOS: 2 (3 dB); default SF LOS: 3 dB; default SF NLOS: A/B → 4 dB, C/D → 5 dB, E/F → 6 dB
  • Default breakpoint distance: A/B/C → 5 m, D → 10 m, E → 20 m, F → 30 m
  • Floor penetration loss according to TGah for CarrierFreq < 1 GHz and TGax for above 1 GHz; floors add attenuation (and the TGah shadow fading below 1 GHz) but no delay; the station is placed 3 m per floor above the AP
  • Taps with zero power in the model tables are removed; the number of paths does not depend on distance, floors or walls

  • Uplink: the coefficient and delay matrices are the transposes of the downlink ones (reciprocal channel, no conjugation), so both directions have the same Doppler shift; positions and orientations are swapped (the moving station is the transmitter)
  • NAN or negative value for any override parameter restores the model default, except XPR_NLOS_linear (see below)
  • Per-snapshot data (coeff, delay, path_gain) is returned as a list of per-snapshot arrays, or stacked into one array along an appended snapshot axis when stack = True

calc_cross_polarization_ratio
Calculate the cross-polarization ratio (XPR) for linear and circular polarization bases
  • Computes aggregate XPR from polarization transfer matrices using the total-power-ratio method: co-pol and cross-pol powers are summed across all qualifying paths per CIR, and XPR is their ratio
  • Inputs are lists so each CIR can have a different number of paths
  • XPR is computed in both the linear V/H basis and the circular LHCP/RHCP basis
  • M is the 2x2 Jones matrix (rows = RX polarisation V/H, columns = TX polarisation V/H), stored column-major with interleaved real/imaginary parts, 8 rows per path: rows 0-1 = (V rx, V tx), rows 2-3 = (H rx, V tx), rows 4-5 = (V rx, H tx), rows 6-7 = (H rx, H tx). Below, M_<rx><tx> names an entry by its receive and transmit polarisation: M_vv = rows 0-1, M_hv = rows 2-3, M_vh = rows 4-5, M_hh = rows 6-7
  • V-XPR and H-XPR are ratios per receive polarisation: V-XPR is the power received in V from V transmission over the power received in V from H transmission; H-XPR likewise for the H receive polarisation
  • The circular entries couple circular patterns through M as get_channels_spherical couples antenna patterns, c(r, t) = r^T M t (plain transpose), with the same circular vectors at both ends, each in that antenna's own (e_theta, e_phi) frame: L = (V, H) = (1, +j) / sqrt(2) (LHCP), R = (1, -j) / sqrt(2) (RHCP); names after the IEEE definition for the time convention exp(+j 2 pi f t) of the library's coefficients exp(-j 2 pi f tau). M_<rx><tx>: M_LL = (M_vv - M_hh + j(M_vh + M_hv)) / 2, M_RR = (M_vv - M_hh - j(M_vh + M_hv)) / 2, M_LR = (M_vv + M_hh + j(M_hv - M_vh)) / 2 (receive L, transmit R), M_RL = (M_vv + M_hh + j(M_vh - M_hv)) / 2. Co-polar means the same circular vector at both ends: the LOS matrix diag(1, -1) is co-polar (handedness kept), diag(1, 1) (one mirrored component, as by a single reflection) is cross-polar
  • LHCP-XPR and RHCP-XPR are ratios per receive polarisation, like V-XPR and H-XPR
  • LOS paths are identified by comparing path length against the direct TX-RX distance dTR; paths with path_length <= dTR + window_size are excluded by default
  • Normalization of M does not affect XPR (cancels in the ratio) but does affect pg
  • If cross-pol power is zero and co-pol is positive, XPR is set to infinity; if both are zero, XPR is set to 0
  • TX/RX positions may be fixed (3, 1) or mobile (3, n_cir)
Usage:
xpr, pg = quadriga_lib.tools.calc_cross_polarization_ratio( powers, M, path_length, tx_pos, rx_pos, \
    include_los, window_size )
Inputs:
  • powers — Path powers on linear scale per CIR; list of length n_cir, each element a 1D array of length n_path
  • M — Polarization transfer matrices with interleaved real/imag parts per CIR; list of length n_cir, each element a 2D array of shape (8, n_path)
  • path_length — Absolute TX-to-RX path lengths per CIR; list of length n_cir, each element a 1D array of length n_path
  • tx_pos — Transmitter position [x; y; z]; (3, 1) (fixed) or (3, n_cir) (mobile)
  • rx_pos — Receiver position [x; y; z]; (3, 1) (fixed) or (3, n_cir) (mobile)
  • include_los — If True, includes LOS and near-LOS paths in the XPR calculation; default: False
  • window_size — LOS exclusion window; paths with path_length <= dTR + window_size are excluded when include_los = False; default: 0.01
Outputs:
  • xpr — XPR on linear scale; (n_cir, 6); columns (0-based):

    Col Description
    0 Aggregate linear XPR (total V+H co-pol / total V+H cross-pol)
    1 V-XPR: sum(abs(M_vv)^2) / sum(abs(M_vh)^2) (receive V)
    2 H-XPR: sum(abs(M_hh)^2) / sum(abs(M_hv)^2) (receive H)
    3 Aggregate circular XPR (total L+R co-pol / total L+R cross-pol)
    4 LHCP XPR: sum(abs(M_LL)^2) / sum(abs(M_LR)^2) (receive L)
    5 RHCP XPR: sum(abs(M_RR)^2) / sum(abs(M_RL)^2) (receive R)
  • pg — Total path gain summed over all paths (including LOS) as 0.5 · sum(powers · (abs(M_vv)^2 + abs(M_hv)^2 + abs(M_vh)^2 + abs(M_hh)^2)); (n_cir,)

Geometry-based stochastic model

A geometry-based stochastic model (GBSM) generates channels from statistics of a type of environment, the scenario (e.g. urban macro-cell with or without line of sight), instead of from the geometry of one site. The functions of this section implement the large-scale part of the model of 3GPP TR 38.901, clause 7.5 steps 1 to 4: path loss, shadow fading, LOS probability, O2I penetration loss and the large-scale parameters (LSPs) of each link, i.e. the spreads of delays and angles, the K-factor and the cross-polarization ratio. They are in the submodule quadriga_lib.gbsm.

The statistics of a scenario are read from a conf file by conf_file_read into two dicts, the scenario parameters scenpar and the path-loss parameters plpar. The folder data/config holds 23 files for TR 38.901 v19.5.0; scenpar_validate completes a parameter set from another source, conf_file_list finds the files and conf_file_write writes them.

Per drop (layout): o2i_loss gives the penetration loss and the indoor distance of each indoor UT; then los_probability evaluates the LOS probability at the outdoor distance d2D - d2D-in. The caller draws the LOS state and the indoor state with sos.rand / sos.randn at the decorrelation distances of the keys LOS_state_lambda and IO_state_lambda, and the O2I variables at the distances of TR 38.901 clause 7.6.3.3 (see o2i_loss). The two state distances apply to all links of a scenario and are stated once in the TR 38.901 files: LOS_state_lambda in the NLOS file, IO_state_lambda in the O2I files; 0 in the other files means "not stated here". Per BS site and scenario (builder): lsf_init_phases draws the random phases once; lsf_draw evaluates them at the links (columns 0 DS, 1 KF, 2 SF, 3 ASD, 4 ASA, 5 ESD, 6 ESA, 7 XPR, 8 absolute TOA: Normal; 9 ground permittivity, 10 UMa environment height: Uniform; each at the decorrelation distance of its key); path_loss returns the path loss and the SF standard deviation; lsp_generate turns the random values into the LSPs of each link and frequency.

Where TR 38.901 and QuaDRiGa differ, the TR behaviour is the default; QuaDRiGa's behaviour is available through an argument where it is still wanted (3D correlation, symmetric square root of the LSP cross-correlation matrix, no clipping of the spreads, outdoor path-loss distance of O2I links). Where QuaDRiGa's behaviour was an error, only the corrected rule is implemented.

Units: positions in m, frequencies in Hz, path loss in dB, DS in s, KF, SF and XPR as linear power ratios, angular spreads in degrees.

conf_file_read
Read and validate a QuaDRiGa scenario configuration file
  • A conf file is a text file with one Key = value assignment per line; % starts a comment; blank lines are allowed; line ends can be LF or CRLF; space and tab are white space; a UTF-8 byte order mark at the start of the file is skipped
  • Keys are case-sensitive names of the characters A-Z, a-z, 0-9 and _; there are four kinds:
    • Scenario parameters: 171 numeric keys with one number each. Keys that are not in the file have their default value.
    • SubpathMethod: one of the words legacy, Laplacian, mmMAGIC; default legacy
    • Path-loss parameters: every key that starts with PL_. PL_model has one name as value. All others have one or more numbers separated by white space.
    • ShortName: an alias for the scenario, one name; can occur several times with different values
  • Any other key is ignored and reported in ignored_keys; its value is not examined
  • A key that is stated more than once has its last value
  • Numbers are decimal with an optional sign, an optional decimal point and an optional exponent (e or E), for example -6.28, .5, 6.2e-07; Inf, +Inf and -Inf are accepted in any case
  • A number beyond the range of a double (1e400) is an error "out of range"; a number below the smallest subnormal reads as 0 (or -0)
  • Numbers are read independent of the locale (the decimal point is always .)
  • Elevation angles are used throughout (+90 deg is up); no key refers to a zenith angle
  • The 171 numeric keys are 138 keys of QuaDRiGa and 33 keys for 3GPP TR 38.901 v19.5.0. With their default of 0 the new keys have no effect.
  • The QuaDRiGa key GR_epsilon (fixed relative permittivity of the ground) is not supported and is reported in ignored_keys; the permittivity is complex and is set in the simulation
  • Raises RuntimeError if the file cannot be opened or is a directory
  • Raises ValueError with file name and line number for a line that is not blank, not a comment and not a well-formed assignment: no =, more or less than one name before the =, a missing value, a word where a number is required or the reverse, a second value or other text after the value, NaN, complex numbers, a number out of range, a PL_ key without a name, a ShortName value stated twice
  • With validate = True, a value that fails the checks of scenpar_validate is an error as well
  • A correlation matrix that is not positive definite is not an error; see lsp_xcorr_chk

  • A failed call does not create a file and leaves an existing file unchanged; an existing file is replaced and keeps its permissions

los_probability
LOS probability of a set of links, TR 38.901 Table 7.4.2-1 and other named models
  • Evaluates the probability that a link is in line-of-sight (LOS) for each link, from its 2D distance and the BS and UT heights, and optionally the soft LOS state of TR 38.901 eq. (7.6-18)
  • Notation: d = d2d_out(l), hB = h_bs(l), hU = h_ut(l) in m, lg = log10, ln the natural logarithm. All results are limited to [0, 1]
  • TR 38.901 v19.5.0 Table 7.4.2-1:
    • 38.901_RMa: 1 for d <= 10, else exp(-(d - 10)/1000)
    • 38.901_UMi: 1 for d <= 18, else 18/d + exp(-d/36)·(1 - 18/d)
    • 38.901_UMa: 1 for d <= 18, else (18/d + exp(-d/63)·(1 - 18/d))·(1 + C'·5/4·(d/100)³·exp(-d/150)) with C' = 0 for hU <= 13, ((hU - 13)/10)^1.5 for 13 &lt; hU <= 23 and 1 for hU > 23; for hU > 13 the formula exceeds 1 slightly just above 18 m (e.g. up to 1.0060 for hU = 22.5), where the limit gives 1
    • 38.901_InH_Mixed (mixed office): 1 for d <= 1.2, exp(-(d - 1.2)/4.7) for 1.2 &lt; d &lt; 6.5, exp(-(d - 6.5)/32.6)·0.32 for d >= 6.5
    • 38.901_InH_Open (open office): 1 for d <= 5, exp(-(d - 5)/70.8) for 5 &lt; d <= 49, exp(-(d - 49)/211.7)·0.54 for d > 49
    • 38.901_InF_SL, 38.901_InF_DL: exp(-d·kinv) with kinv = -ln(1 - r)/d_clutter
    • 38.901_InF_SH, 38.901_InF_DH: with kinv = -ln(1 - r)/d_clutter: 1 for hU >= h_c (UT above the clutter); exp(-d·kinv·(h_c - hU)/(hB - hU)) for hB > hU (TR: k = -d_clutter/ln(1 - r)·(hB - hU)/(h_c - hU)); exp(-d·kinv) (the rule of SL and DL) for hB <= hU &lt; h_c, where the TR formula has a BS above the UT and would give k <= 0. r = 0 gives 1
    • 38.901_InF_HH: 1
    • 38.901_SMa (TR v19): 1 for d <= 10 or hB <= hU, else exp(-d·(k_com + k_res + k_veg)) with k_x = -ln(1 - r_x)/d_clutter·max(h_x - hU, 0)/(hB - hU), heights h_com = 20, h_res = 8, h_veg = 15 m, densities r_com = 0.02, r_res = 0.18, r_veg = r_clutter; the TR writes max(., 0) only for the residential term, which gives the same values for hU &lt; 15 m (the TR range)
  • Defaults of the clutter arguments (NaN), TR 38.901 Table 7.2-4 and Table 7.8-7 for InF, Table 7.4.2-1 for SMa:
    • InF_SL: r = 0.2, d_clutter = 10 m; InF_DL: r = 0.6, d_clutter = 2 m
    • InF_SH: r = 0.2, d_clutter = 10 m, h_c = 2 m; InF_DH: r = 0.6, d_clutter = 2 m, h_c = 6 m
    • SMa: d_clutter = 30 m, r_veg = 0 (no vegetation; 0.1 sparse, 0.2 dense vegetation); h_clutter is not used
    • The other models ignore the clutter arguments (they are validated for every model)
  • TR 38.811 (via QuaDRiGa), 38.811_DenseUrban, 38.811_Urban, 38.811_Suburban, 38.811_Rural: the LOS probability in percent over the elevation atan2(hB, d) in degrees (absolute BS height), linear interpolation over the grid -90, 0, 10, ..., 90 deg, times 0.01:
    • DenseUrban: 0, 0, 28.2, 33.1, 39.8, 46.8, 53.7, 61.2, 73.8, 82.0, 98.1
    • Urban: 0, 0, 24.6, 38.6, 49.3, 61.3, 72.6, 80.5, 91.9, 96.8, 99.2
    • Suburban and Rural: 0, 0, 78.2, 86.9, 91.9, 92.9, 93.5, 94.0, 94.9, 95.2, 99.8
  • QuaDRiGa, QuaDRiGa_Industrial: min(1, exp(-(d + 20)/80)·exp(min(hB, 8)/5 - 1))
  • LOS: 1, NLOS: 0
  • Soft LOS state (TR 38.901 eq. 7.6-18), computed when rnd_g and fc are both given (not None): los_soft(l, k) = 1/2 + atan(sqrt(20/lambda_k)·(rnd_g(l) + F(p_los(l))))/pi, lambda_k = c/fc(k) with c = 299792458 m/s and F(p) = sqrt(2)·erfinv(2p - 1) the inverse of the standard normal CDF (accurate to 1e-10·max(1, abs(F)) for p in [1e-12, 1 - 1e-12]). p = 1 gives 1, p = 0 gives 0. los_soft > 0.5 exactly when rnd_g > -F(p), which has the probability p for rnd_g from N(0,1)
  • The LOS state itself (a draw against p_los) and its spatial correlation are the caller's: e.g. a spatially consistent uniform value from sos.rand, or rnd_g from sos.randn, at the decorrelation distance of the scenario key LOS_state_lambda (TR 38.901 Table 7.6.3.1-2). The key applies to all links of a scenario and is stated only in its NLOS conf file (0 in the LOS and O2I files means "not stated here"). The LOS_state_lambda of the InF conf files is d_clutter / 2 of the TR defaults; it does not follow a d_clutter argument, so a caller who changes d_clutter passes its own correlation distance
  • O2I UTs: Table 7.4.2-1 uses the outdoor distance d2d_out = d2D - d2D-in with d2D-in from o2i_loss, which therefore runs first; the caller clamps d2d_out at 0 (negative distances are rejected). Indoor scenarios (InH, InF) pass the 2D distance
  • Validation, in this order: the model name; d2d_out finite and >= 0; h_bs and h_ut with 1 or n_link elements and finite; d_clutter NaN or finite and > 0, r_clutter NaN or in [0, 1), h_clutter NaN or finite and >= 0 (for every model); if los_soft is computed: rnd_g with n_link finite elements, fc non-empty, finite and > 0. Without los_soft, a given rnd_g or fc is ignored. All errors are raised as ValueError

lsf_draw
Spatially correlated normalized random values of the large-scale generators at a set of links
  • Evaluates the 11 large-scale fading generators of lsf_init_phases at the links: column 0 DS, 1 KF, 2 SF, 3 ASD, 4 ASA, 5 ESD, 6 ESA, 7 XPR, 8 absolute TOA (Normal(0,1)), 9 ground permittivity, 10 UMa environment height hE (Uniform(0,1)); each generator with the sum-of-sinusoids frequencies of preset at its own decorrelation distance (a distance of 0 is used as 0.1 m)
  • scenpar is completed and validated as in lsf_init_phases; the messages of scenpar_validate pass through unchanged
  • Single mobility (dual_mobility = False): column g is the field of generator g at the Rx position, x_g = s_g(rx) with s_g(x) = sqrt(2/n_coeff) · sum_n cos( 2·pi · f_n·x + phi_n ) and the phases of slice 0; the values do not depend on tx_pos
  • Dual mobility: the Tx is a second device. Its side uses slice 1, i.e. the field of the mirror generator m(g) at the Tx position (ASD and ASA, ESD and ESA exchanged). Self-mirrored generators (DS, KF, SF, XPR, TOA, columns 9 and 10) share one map: x_g = ( s_g(rx) + s_g(tx) ) / sqrt( 2 + 2·A_g(D) ), with the Tx-Rx distance D and the ACF A_g of the preset, linearly interpolated. The pairs are two maps: x_g = ( s_g(rx) + s_m(tx) ) / sqrt(2). Columns 3 to 6 thus stay Normal(0,1), and ASD/ASA and ESD/ESA have the correlation ( A_g(D) + A_m(D) ) / 2 at the Tx-Rx distance, 1 at D = 0 (then the two columns are equal)
  • Swap reciprocity in dual mobility: swapping tx_pos and rx_pos leaves columns 0, 1, 2, 7, 8, 9, 10 unchanged and swaps column 3 with 4 and column 5 with 6, exactly (the same evaluations in swapped roles), also for unequal decorrelation distances and with bias-removed phases, when both calls use the same phase
  • Uniform columns 9 and 10: 0.5 · erfc( -x / sqrt(2) ) of the Normal value
  • horizontal = True: the positions are projected on the x-y plane (z = 0) and the values do not depend on z; False: 3D positions. D is measured in the same space
  • 2D and 3D mode give the same per-link statistics. In 3D mode the height separates the floors: the LSPs of UTs on different floors are correlated by the ACF of their height difference, while TR 38.901 (Table 7.5-6 note 3) assumes no correlation between floors. floor_id is therefore not accepted with horizontal = False
  • Floors: links with different floor IDs see different fields, links with equal IDs share one field. Floor q adds the offsets 2·pi · k · n / N + psi_b(n) to the phases of all generators on both sides, with N = n_coeff, k = q mod N, b = q div N, n = 0 ... N-1, psi_0 = 0 and psi_b(n) = 2·pi · u_n for b >= 1, where u_n are the uniform numbers of a std::mt19937_64 seeded with b (the upper 53 bits of each raw output times 2^-53). Floor 0 and floor_id = None give the same values
  • Fields of two floors are uncorrelated at equal horizontal positions (TR 38.901 Table 7.5-6 note 3): exactly for two IDs in the same block of N IDs, with a random residual of standard deviation 1/sqrt(2N) for IDs in different blocks (0.044 for 256 sinusoids). At other horizontal lags the cross-correlation of two floors is not zero (up to about 0.16 for 256 sinusoids), the same level as for random offsets. Mirror relations and swap reciprocity hold per floor
  • floor_id is the caller's floor index of the UT, starting at 0: for the UT heights hUT = 3·(n_fl - 1) + 1.5 of TR 38.901 Table 7.2-1 it is n_fl - 1; outdoor UTs use 0. The IDs are read as float64, so they must be below 2^53 (larger values would not be exact)
  • Dual mobility with floors: floor_id is one value per link and its offsets are added on both sides, i.e. both devices of a link are on the link's floor. A Tx device on another floor than its Rx (e.g. a D2D link between two floors) is evaluated on the floor of the Rx, so the same Tx device sees different fields on links to Rx devices on different floors
  • The value of a link does not depend on the other links of the call; n_link = 0 returns an array of shape (0, 11)
  • Precision: the sinusoids are evaluated by sos.val with the AVX2 kernel where available (sine and cosine in single precision, accumulation in double); the values deviate from a double-precision evaluation by less than 4e-7 · sqrt(2 · n_coeff) (9e-6 for 256 sinusoids)
  • preset and horizontal must be those of lsf_init_phases. A wrong preset with the same number of sinusoids (e.g. Exp256 for Comb256) cannot be detected
  • The flags dual_mobility and horizontal take a bool or numpy.bool_; None selects the default, any other type raises TypeError
  • Validation order: floor_id (non-negative integers below 2^53, checked by the wrapper), positions (3 columns, rows of tx_pos, finite values), preset, scenpar, size of phase, finite phase, length of floor_id, floor_id with horizontal = False
Usage:

lsf_init_phases
Draw the random phases of the large-scale generators of one BS site and scenario
  • The large-scale fading (LSF) of a site is described by 11 spatially correlated sum-of-sinusoids generators, one column each: 0 DS, 1 KF, 2 SF, 3 ASD, 4 ASA, 5 ESD, 6 ESA, 7 XPR, 8 absolute TOA (Normal fields), 9 ground permittivity, 10 UMa environment height hE (Uniform fields)
  • Their decorrelation distances are the scenario parameters DS_lambda, KF_lambda, SF_lambda, AS_D_lambda, AS_A_lambda, ES_D_lambda, ES_A_lambda, XPR_lambda, absTOA_lambda, SC_lambda and again SF_lambda for hE; a decorrelation distance of 0 is used as 0.1 m. The generator of column 8 exists also when the absolute TOA is disabled
  • This function draws the phases; lsf_draw evaluates them at the links. The caller stores phase and evaluates the same fields again along tracks or on maps
  • scenpar is completed with the defaults of missing keys and validated as in scenpar_validate; its messages (e.g. for an unknown key or a negative decorrelation distance) pass through unchanged as ValueError. An invalid value of a key that is not used here raises as well
  • Slice 0 (Rx side) holds the phases of the 11 generators. Without bias removal it equals quadriga_lib.sos.init_phases( n_coeff, 11, seed ) of sos.init_phases, with n_coeff the number of sinusoids of preset. The same seed gives the same phases
  • Slice 1 (Tx side) is always the mirror of slice 0: phase[:, :, 1] = phase[:, [0, 1, 2, 4, 3, 6, 5, 7, 8, 9, 10], 0], i.e. ASD and ASA and ESD and ESA are exchanged, all others mirror themselves. For dual mobility the departure spreads at the Tx are thus the arrival spreads of the Tx as a second device
  • Bias removal (remove_bias = True, rx_pos given, n_link > 2): one realisation of a correlated field has a non-zero mean over a drop. For each Normal generator (columns 0 to 8) one common phase offset is applied with sos.remove_bias, so that the sample mean of its field over the positions is exactly 0. Single mobility: over the Rx positions; tx_pos is not used. Dual mobility: over the Rx and Tx positions together (2·n_link positions), because the field of a generator is shared by both devices (the Tx side of ASD is the ASA field); tx_pos is then required. The Uniform generators 9 and 10 are never corrected
  • The correction is applied to slice 0 and the Tx side is mirrored afterwards, so the mirror relation holds exactly with and without bias removal. Swapping tx_pos and rx_pos in dual mobility gives the same phases up to rounding (the sums over the positions are formed in another order)
  • Consequences for lsf_draw at the same positions: in single mobility the link mean of columns 0 to 8 is 0; in dual mobility the link mean of DS, KF, SF, XPR and TOA is 0 when all links have the same Tx-Rx distance (the normalisation is then the same for all links), while ASD/ASA and ESD/ESA have a zero link mean only approximately (their two devices see different fields, each corrected over the union of the positions)
  • The positions are used as in lsf_draw: projected on the x-y plane (z = 0) for horizontal = True, in 3D for horizontal = False. preset and horizontal must be the same in lsf_draw
  • 2D mode: all positions in rx_pos are treated as one field (floor 0): one phase correction per generator cannot zero the means of several floor fields at once. For a drop with UTs on several floors pass the positions of one floor (e.g. the links of floor 0) or set remove_bias = False; the fields of the other floors keep their sample mean. 3D mode (horizontal = False): there are no floor IDs (the height separates the floors) and the correction covers all given positions as one 3D field
  • 2D and 3D mode give the same per-link statistics. In 3D mode the LSPs of UTs on different floors are correlated by the ACF of their height difference, while TR 38.901 (Table 7.5-6 note 3) assumes no correlation between floors
  • The correction removes variance: the field is conditioned on a zero mean over the positions, which costs little only when the positions spread over many decorrelation distances (see sos.remove_bias)
  • With fewer than 3 positions, without rx_pos or with remove_bias = False no correction is made
  • TR 38.901 clause 7.4.4 literally (exponential ACF, no bias removal): preset = "Exp256" and remove_bias = False; the defaults Comb256 and the bias removal are QuaDRiGa choices
  • Reason for Comb256: the TR gives the exponential ACF (eq. 7.4-5) as a fit "with sufficient accuracy", not as an exact requirement; its kink at zero distance makes the values evolve roughly along a track. Comb256 (Gaussian near zero, exponential tail, same decorrelation distance) evolves smoothly
  • The flags dual_mobility, remove_bias and horizontal take a bool or numpy.bool_; None selects the default, any other type raises TypeError
  • Validation order: seed, preset, scenpar, then the positions (3 columns, rows of tx_pos 1 or n_link when both are given, finite values), then the requirement of tx_pos for the bias removal in dual mobility
Usage:

Inputs:
  • scenpar — Scenario parameters; dict as returned by conf_file_read or scenpar_validate (the entry SubpathMethod is ignored), or any subset of its keys; missing keys have their default value; None = all defaults; only the 10 decorrelation distances are used
  • seed — Seed of the random phases; int from -1 to 2^63-1; -1 = system random device, a new set of phases on each call; default: -1

lsp_generate
Large-scale parameters of a set of links from normalized random values
  • Generates the 8 large-scale parameters (LSPs) of TR 38.901 clause 7.5 step 4 per link and frequency: delay spread DS, Ricean K-factor KF, shadow fading SF, azimuth spreads of departure and arrival ASD, ASA, elevation spreads of departure and arrival ESD, ESA and cross-polarization ratio XPR. The random values rnd are the normalized, spatially correlated values of lsf_draw (columns 0 to 7 Normal(0,1) for the 8 LSPs, column 8 Normal(0,1) for the absolute TOA, column 9 Uniform(0,1) for the ground permittivity; column 10 is not used here)
  • scenpar is completed with the defaults of missing keys and validated as in scenpar_validate; its messages pass through unchanged. An invalid value of a key that is not used here raises as well
  • Mean and standard deviation in the log domain, per link l and frequency k, with the key prefix P of the LSP (DS, KF, SF, AS_D, AS_A, ES_D, ES_A, XPR), the 2D distance d2D, the Tx height hBS = tx_pos.z and the Rx height hUT = rx_pos.z: d = max(d2D, 1e-4), h = max(hBS, 1e-4), a = atan(h / d) (elevation in rad), f' = max(fc / 1e9, LSP_fc_min) (frequency in GHz, limited from below by LSP_fc_min for all LSP terms); mu = P_mu + P_gamma·lg(P_omega + f') + P_epsilon·lg(d) + P_zeta·lg(h) + P_alpha·lg(a); s = max(0, P_sigma + P_delta·lg(P_omega + f')); sigma = max(0, s + P_kappa·lg(d) + P_tau·lg(h) + P_beta·lg(a)). The standard deviation is limited at 0 after all terms, since a negative value would flip the sign of the realization and its cross-correlations. SF has no mean keys (mean 0). A frequency term with the coefficient 0 contributes 0; an active one (P_gamma or P_delta not 0) requires P_omega + f' > 0 at every frequency. The multiplying coefficients (P_sigma, P_gamma, P_delta, P_epsilon, P_zeta, P_alpha, P_kappa, P_tau, P_beta, ES_D_mu_A to ES_D_mu_D, P_omega of an active frequency term) must be finite; P_mu and ES_D_mu_min may be infinite
  • DS with the V/S term of TR 38.901 Table 7.5-6 Part-3 (InF): if DS_VS > 0, mu += lg(DS_VS_a·DS_VS + DS_VS_b). The InF files set DS_VS for the hall of their calibration scenario; a caller with another hall sets DS_VS (V/S in m) in its copy of scenpar
  • ESD with the terms of TR 38.901 Tables 7.5-7 to 7.5-12: `mu += ES_D_mu_A·d/1000 + ES_D_mu_B·hUT + ES_D_mu_C·abs(hUT - h) + ES_D_mu_D·max(hUT - h, 0), then the floor mu = max(mu, ES_D_mu_min)`
  • Units of mean and std: DS in lg(s); ASD, ASA, ESD, ESA in lg(deg); KF, SF and XPR in dB
  • sf_sigma (e.g. from path_loss) replaces the SF standard deviation per link and frequency, also in lsp_sigma; it must be finite and >= 0 (a negative value would flip the sign of the shadow fading)
  • Cross-correlation: x = Q·s with s = rnd(l, 0..7) and a root Q of the LSP cross-correlation matrix R of scenpar (Q·Q^T = R). cholesky = true (TR 38.901 clause 7.5 step 4): Cholesky factorization in the TR order [SF, KF, DS, ASD, ASA, ESD, ESA], XPR appended last; the SF value is passed through (x_SF = s_SF). cholesky = false: the symmetric square root of R (principal root, legacy QuaDRiGa behaviour); it does not depend on the order of the parameters. Both raise ValueError if R is not positive definite
  • The same x is used for all frequencies of a link (TR 38.901 clause 7.6.5)
  • Linear values: lsp = 10^(mu + sigma·x) for DS, ASD, ASA, ESD, ESA; 10^(0.1·(mu + sigma·x)) for KF, SF, XPR. clip_spreads = true (TR 38.901 clause 7.5 step 4): ASD and ASA are limited to 104 deg, ESD and ESA to 52 deg; lsp_mu and lsp_sigma are not affected
  • rnd = numpy.zeros((n_link, 11)) gives the median LSPs; lsp_mu and lsp_sigma are the mean and std without any randomness
  • Absolute TOA offset (TR 38.901 clause 7.6.9): active if absTOA_mu > -30, then abs_toa = min(10^(absTOA_mu + absTOA_sigma·rnd(l, 8)), 2·absTOA_Lmax / c) with c = 299792458 m/s, without the bound if absTOA_Lmax = 0 (absTOA_sigma must be finite); 0 if not active. The InF and InH NLOS files set absTOA_Lmax to the largest dimension of the hall or office of their calibration scenario; a caller with another hall sets the key; in the TR 38.901 files the offset is active in all NLOS and O2I files (an O2I link has no LOS ray) and off in the LOS files
  • Ground permittivity with U = rnd(l, 9) and f = fc / 1e9 (not limited by LSP_fc_min): dry ground 3 + j·0.003·f^1.34, medium 30.4·f^-0.47 + j·0.18·f^1.05, wet 31.3·f^-0.48 + j·0.63·f^0.77; linear interpolation from dry (U = 0) to medium (U = 0.5) to wet (U = 1). The imaginary part is >= 0; TR 38.901 eq. (7.6-40) writes the complex permittivity with the opposite sign of the imaginary part, so the TR reflection formulas take the complex conjugate gr_eps.conj(). The permittivity is always computed, so column 9 of rnd must always be in [0, 1]
  • The three ground types are QuaDRiGa's fits (as in QuaDRiGa's gen_lsf_parameters), not the models of TR 38.901 Table 7.6.8-1: very dry ground agrees, medium and wet ground differ (e.g. at 3.5 GHz medium 16.87 + j·0.67 here, 13.23 + j·1.39 for medium dry ground of the table; wet j·1.65 vs. j·3.93). A caller who needs the table values computes them with eq. (7.6-40) to (7.6-42)
  • EoD offset in degrees, positive = up (the negative of the ZOD offset of TR 38.901 Tables 7.5-7 to 7.5-12), with f', d, h as above: e = EoD_offset_e + EoD_offset_e_gamma·lg f'; if EoD_offset_b > 0: `e += 10^((EoD_offset_a + EoD_offset_a_gamma·lg f')·lg(max(EoD_offset_b, d)) + EoD_offset_c + EoD_offset_c_gamma·lg f' + EoD_offset_c_hUT·hUT); if EoD_offset_hcl > 0 and hUT < EoD_offset_hcl`: e += (atan((EoD_offset_hcl - h)/d) - atan((hUT - h)/d))·180/pi. The coefficients EoD_offset_e, _e_gamma, _a, _a_gamma, _c, _c_gamma, _c_hUT must be finite
  • n_link = 0 gives outputs with 0 rows
  • Validation order: positions, fc, rnd, sf_sigma, scenpar, positive definiteness, column 9 of rnd, the coefficients and frequency terms of the 8 LSPs, the EoD_offset_ coefficients and absTOA_sigma; all errors are raised as ValueError
  • complex = True returns the permittivity as one complex array gr_eps = gr_eps_re + 1j·gr_eps_im; complex = False returns the two real arrays gr_eps_re, gr_eps_im in its place (one more output)
  • The flags cholesky, clip_spreads and complex take a bool or numpy.bool_; None selects the default, any other type raises TypeError
Usage:

  • fc — Carrier frequencies in Hz, finite and > 0; (n_freq,)

o2i_loss
O2I building or car penetration loss of a set of UTs, TR 38.901 clause 7.4.3
  • Draws for each UT one of the given penetration-loss models and evaluates its loss at each carrier frequency, from four normalized random values per UT; f = fc / 1e9 in GHz, lg = log10
  • Material losses of TR 38.901 v19.5.0 Table 7.4.3-1 in dB: L_glass = 2 + 0.2 f, L_IRR = 25.4 + 0.11 f (IRR glass, Release 19 value), L_concrete = 5 + 4 f, L_plywood = 1.03 + 0.17 f; external wall tw(p1, L1, p2, L2) = 5 - 10·lg(p1·10^(-L1/10) + p2·10^(-L2/10))
  • Models, with N = rnd(u, 3) and the indoor 2D distance d2din:
    • low (low-loss, Table 7.4.3-2): tw(0.3, L_glass, 0.7, L_concrete) + 0.5·d2din + 4.4·N
    • high (high-loss, Table 7.4.3-2): tw(0.7, L_IRR, 0.3, L_concrete) + 0.5·d2din + 6.5·N
    • low_A (low-loss A, Table 7.4.3-2): tw(0.3, L_glass, 0.7, L_plywood) + 0.5·d2din + 4.4·N
    • legacy_6GHz (backward compatible model for single-frequency simulations below 6 GHz, Table 7.4.3-3): 20 + 0.5·d2din, no deviation; it goes with a shadow-fading std of 7 dB (the O2I conf files of UMa and UMi have SF_sigma = 7)
    • car (clause 7.4.3.2): 9 + 5·N; car_metal (metallized car windows): 20 + 5·N; no indoor distance
  • Columns of rnd: 0 = Uniform(0,1) for the model choice, 1 and 2 = Uniform(0,1) for the indoor distance, 3 = Normal(0,1) for the deviation (sigma_P of Table 7.4.3-2, the car loss)
  • Model choice per UT: Ccum_j = (w_0 + ... + w_j)/sum(w); the model is the smallest j with rnd(u, 0) &lt; Ccum_j, or, if there is none, the last j with w_j > 0. A model with weight 0 is never chosen
  • Indoor distance: low, high, low_A: d2din = min(rnd(u, 1), rnd(u, 2))·d2d_in_max, the minimum of two uniforms of clause 7.4.3.1; legacy_6GHz: d2din = rnd(u, 1)·d2d_in_max (one uniform, Table 7.4.3-3); car, car_metal: 0
  • The caller draws rnd with sos.rand and sos.randn at the correlation distances of TR 38.901 clause 7.6.3.3 (building type 50 m for column 0, d2D-in 25 m for columns 1 and 2, sigma_P 10 m for column 3) and adds loss to the path loss of the indoor UT. d2d_in gives the outdoor distance d2D - d2D-in for los_probability (call o2i_loss first) and is the input of the legacy outdoor distance of path_loss
  • Applicability (Table 7.4.3-2): RMa uses low only, InF high only; UMa, UMi: low and high; SMa: low, high and low_A. TR maximum indoor distance: 25 m for UMa, UMi and SMa commercial buildings, 10 m for RMa and SMa residential buildings (conf-file key O2I_d2D_in_max). The TR SMa layout has 90 % residential and 10 % commercial buildings (Table 7.2-5): split the UTs by building type and call o2i_loss once per type
  • Validation, in this order: fc non-empty, finite and > 0; rnd with 4 columns, columns 0 to 2 in [0, 1], column 3 finite; models non-empty, each a known name; weights with one finite element >= 0 per model and a sum of 1 within 1e-6; d2d_in_max finite and >= 0. All errors are raised as ValueError

Inputs:
  • fc — Carrier frequencies in Hz, finite and > 0; (n_freq,)
  • rnd — Random values per UT: Uniform(0,1) model choice, Uniform(0,1) d2D-in #1, Uniform(0,1) d2D-in #2, Normal(0,1) deviation; (n_ut, 4), n_ut = 0 allowed
  • models — Models to mix: low, high, low_A, legacy_6GHz, car, car_metal; list of str or one str; n_model entries
  • weights — Probability of each model, >= 0, sum 1; (n_model,)
  • d2d_in_max — Maximum indoor 2D distance in m, finite and >= 0 (conf-file key O2I_d2D_in_max); default: 25.0
Outputs:
  • loss — Penetration loss in dB; (n_ut, n_freq)
  • d2d_in — Indoor 2D distance in m, 0 for the car models; (n_ut,)
  • model_index — Chosen model per UT, 0-based index into models; uint64; (n_ut,)

path_loss
Path loss and shadow-fading standard deviation of a set of links
  • Evaluates one of the 10 parametric path-loss models of the QuaDRiGa conf files for every link and carrier frequency. plpar is the dict of conf_file_read: its entry model is the model (value of PL_model), the other entries are the PL_ keys without the prefix; the TR 38.901 v19.5.0 conf files in data/config reproduce Table 7.4.1-1 with them
  • Notation: f = fc / 1e9 in GHz (not limited by LSP_fc_min); d3, d2 the 3D and 2D distance in m; hBS, hUT the z coordinates of Tx and Rx (no ground model); [X] the value of key X, or its default if the key is missing (X = v in the lists below); PL1(x) = A1·lg(x) + B + C·lg(f) + D·x; sf the shadow-fading std
  • Models, required keys and defaults:
    • constant (A): pl = A
    • logdist (A, B, C; SF optional): pl = A·lg(d3) + B + C·lg(f); sf = [SF] if present
    • logdist_simple (A, B): pl = A·lg(d3) + B
    • winner_los (A1, A2, B1, B2, C1, C2, D1, D2, E1, E2, F1, F2, sig1, sig2): hb = max(hBS, 1.5), hm = max(hUT, 1.5) of each link; G = B1 + C1·lg f + D1·lg hb + E1·lg hm, H = B2 + C2·lg f + D2·lg hb + E2·lg hm, breakpoint bp = 10^((H - G)/(A1 - A2)); d2 <= bp: pl = A1·lg d2 + G + F1·hm, sf = sig1; else pl = A2·lg d2 + H + F2·hm, sf = sig2 (continuous at bp for F1 = F2); A1 and A2 must differ
    • winner_nlos (A1..A3, Ah1..Ah3, B1..B3, C1..C3, D1..D3, E1..E3, F1..F3): hb, hm as winner_los; L_j = (A_j + Ah_j·lg hb)·lg d2 + B_j + C_j·lg f + D_j·lg hb + E_j·lg hm + F_j·hm; pl = L_1 for f &lt; 1.5, L_2 for 1.5 <= f &lt; 2, L_3 for f >= 2
    • winner_pathloss (A, B, C, X; SF optional): pl = A·lg d3 + B + C·lg(f/5) + X; sf = [SF] if present
    • dual_slope (A1 or A, B, E; A2 = A1, C = 0, D = 0, hE = 0, hE_rand = 0, sig1, sig2 optional): hb = max(hBS, 1.1·hE, 0.1), hm = max(hUT, 1.1·hE, 0.1); dBP = E·f·(hb - hE)·(hm - hE); d2 <= dBP: pl = PL1(d3), sf = [sig1]; d2 > dBP: pl = PL1(dBP3) + A2·lg(d3/dBP3), sf = [sig2] (each only if present), with the 3D breakpoint distance dBP3 = sqrt(dBP² + (hb - hm)²). This is Table 7.4.1-1 for UMa, UMi, InH and InF; for RMa and SMa LOS the TR uses the 2D breakpoint distance in PL2, which differs by at most 0.034 dB over the TR ranges
    • tripple_slope (A1 or A, B, E1 or E; A2 = A1, A3 = A2, C = 0, D = 0, E2 = E1, hE1 = 0, hE2 = 0, sig1..sig3 optional): hb = max(hBS, 1.1·hE1, 1.1·hE2, 0.1), hm the same; dBPj = Ej·f·(hb - hEj)·(hm - hEj), dBP1 = min(dBP1, dBP2), dBPj3 = sqrt(dBPj² + (hb - hm)²); LBP1 = PL1(dBP13), LBP2 = LBP1 + A2·lg(dBP23/dBP13); d2 <= dBP1: PL1(d3), sf = [sig1]; dBP1 &lt; d2 <= dBP2: LBP1 + A2·lg(d3/dBP13), sf = [sig2]; d2 > dBP2: LBP2 + A3·lg(d3/dBP23), sf = [sig3]
    • nlos (An, Bn; the dual_slope keys if LOSmax != 0; Cn, Dn, D1n, D2n, D3n, En, E1n, E2n, E3n, Fn, G1n = 0, G2n = 1, LOSmax = 1, sig optional; Ax, Bx, Cx = 0): hb = max(hBS, 0.1), hm = max(hUT, 0.1); `PLn = An·lg d3 + Bn + Cn·lg f + Dn·lg hb + D1n·lg(hb)/hb + D2n·lg(hb)/hb² + D3n·hb + En·lg hm + E1n·lg(hm)/hm + E2n·lg(hm)/hm² + E3n·hm + Fn·lg(hb)·lg(d3) + G1n·(lg(G2n·hm))²; pl = PLn`; if [LOSmax] != 0: pl = max(pl, PL_LOS) with the dual_slope loss of the same parameters (incl. the random hE); if Ax, Bx or Cx is present: pl = max(pl, Ax·lg d3 + Bx + Cx·lg f) (e.g. the InF-SL term of InF-DL); sf = [sig] if present
    • satellite (A = 20, B = 32.45, C = 20, D = 0, usePLa = 1): sa = min(hBS / d3, 1) with the absolute Tx height; pl = +Inf if sa <= 0; else pl = A·lg d3 + B + C·lg f + D·lg(asin(sa)) + PLa with PLa = Z(f) / sa if usePLa != 0, else 0; Z(f) is the zenith attenuation by atmospheric gases (93 values from 1 to 100 GHz, linear interpolation, constant beyond both ends)
    • no model (plpar is None, {} or has no entry model): pl = 0
  • New keys of the TR 38.901 v19 files: hE_rand (non-zero: random environment height of UMa), LOSmax (0: no maximum with the LOS term in nlos), Ax, Bx, Cx (additional term in the maximum of nlos)
  • Random environment height (TR 38.901 Table 7.4.1-1, note 1), in dual_slope and the LOS term of nlos when [hE_rand] != 0 and rnd_he is given, per link with u = rnd_he(l), d = d2, raw hUT: g = 0 for d <= 18, else 1.25·(d/100)³·exp(-d/150); C' = 0 for hUT &lt; 13, ((hUT - 13)/10)^1.5 for hUT <= 23, else 1; C = C'·g, p1 = 1/(1 + C); n = size of the set {12, 15, ..., hUT - 1.5}; hE = 1 if C = 0, n = 0, u &lt; p1 or p1 rounds to 1 (C below 1.1e-16, e.g. beyond about 7.5 km at hUT = 20), else hE = 12 + 3·min(floor((u - p1)/(1 - p1)·n), n - 1). The UT height is then clamped to hm = max(hUT, hE + 0.1, 0.1) instead of 1.1·hE: for hE = 1 this is the fixed-hE clamp (also below hUT = 1.1), and the drawn heights 12, 15, ... are not affected (hUT - hE >= 1.5). Without rnd_he the fixed [hE] is used. rnd_he is column 10 of lsf_draw, a spatially consistent uniform value: TR 38.901 draws hE independently per link and gives no decorrelation distance; the library makes it spatially consistent in the sense of clause 7.6.3 with the decorrelation distance SF_lambda, so nearby UTs of a site share hE. Along a track hE switches between its discrete values where u crosses a threshold, and the loss beyond the breakpoint steps there; evaluate rnd_he once per track segment to avoid this
  • Distances: d3, d2 are the geometric distances (TR 38.901 eq. 7.4-1: for an indoor UT d3D-out + d3D-in). If d2d_in is given (legacy mode), a link with d2d_in(l) > 0 uses the outdoor distance instead: din = min(d2d_in, d2), d3in = d3·din/d2 (d3 if d2 = 0), limited to d3; if d3 - d3in &lt; 10: d3in = d3 - 10 (minimum outdoor distance 10 m), then max(d3in, 0); p = d3in/d3 (0 if d3 = 0); d3 = d3 - d3in, d2 = d2·(1 - p). A link with d2d_in(l) = 0 is an outdoor link and keeps the geometric distances (no 10 m rule). Then d3 = max(d3, 0.1), d2 = max(d2, 0.1). The O2I penetration loss is not added; add the output of o2i_loss
  • Default shadow-fading std, where a model does not set it: the SF std of the LSP formula of lsp_generate with the geometric distance, `sf = max(0, max(0, SF_sigma + SF_delta·lg(SF_omega + f')) + SF_kappa·lg(d) + SF_tau·lg(h) + SF_beta·lg(atan(h/d))) with d = max(d2D, 1e-4), h = max(hBS, 1e-4)`, f' = max(f, LSP_fc_min); for scenario files without such terms this is SF_sigma. Passing sf_sigma to lsp_generate is then neutral. SF_sigma, SF_delta, SF_kappa, SF_tau, SF_beta must be finite, and a frequency term with SF_delta != 0 requires a finite SF_omega and SF_omega + f' > 0
  • Validation: positions, fc, the lengths of d2d_in and rnd_he, their values, the model name, the parameters of the model in the order the model reads them (a required key that is missing raises Path-loss model '<model>' requires the parameter '<key>'., naming A1 for "A1 or A" and E1 for "E1 or E"; every key that the model reads must have exactly one value, which must be finite; keys not read are ignored), the breakpoint factors E, E1, E2 and G2n of nlos (> 0) and A1 != A2 of winner_los, then scenpar (scenpar_validate, its messages pass through), then the SF coefficients and frequency term; all errors are raised as ValueError
  • The models are evaluated as written for any positive frequency, also outside their validity range
Usage:

Inputs:

Math functions


cart2geo
Convert elementwise Cartesian coordinates to azimuth/elevation angles and vector length
  • Computes: length = sqrt(x² + y² + z²), az = atan2(y, x), el = asin(clamp(z / length, -1, 1))
  • Inputs are arbitrary 3D vectors (not required to be unit length); length returns the Euclidean norm
  • z / length is clamped to [-1, 1] before asin to guard against length == 0 and rounding artifacts
  • Azimuth is in [-pi, pi], elevation in [-pi/2, pi/2]; elevation pi/2 points to the zenith, 0 to the horizon
  • Special values of atan2 as in numpy (e.g. atan2(0, -0) = pi); NaN input gives NaN in az, el and length
  • Two mutually exclusive input forms: a combined array cart of shape (3, n, m), or separate x, y, z of shape (n, m)
  • The AVX2 kernel computes the angles in single precision (length and z / length in double precision); use use_kernel = 1 for full double precision
Usage:
geo_coords     = quadriga_lib.tools.cart2geo( cart, y, z, combine, use_kernel )
az, el, length = quadriga_lib.tools.cart2geo( cart, y, z, combine=False )
Inputs:
  • cart — Combined Cartesian coordinates (3, n, m); or, when y and z are given, the x-coordinates (n, m)
  • y — Y-coordinates (n, m); provide together with z for separate inputs; default: None
  • z — Z-coordinates (n, m); provide together with y; default: None
  • combine — If True, return a single (3, n, m) array; if False, return separate az, el, length arrays; default: True
  • use_kernel — Kernel: 0 = auto (AVX2 if available, else GENERIC), 1 = GENERIC, 2 = AVX2 (throws if unavailable); other values raise; default: 1
Outputs:
  • geo_coords — Combined geographic coordinates (3, n, m); row 0 = azimuth, row 1 = elevation, row 2 = vector length; returned when combine is True
  • az — Azimuth angles (n, m); returned when combine is False
  • el — Elevation angles (n, m); returned when combine is False
  • length — Vector length (n, m); returned when combine is False

geo2cart
Convert elementwise azimuth/elevation angles to Cartesian coordinates
  • Conversion: x = cos(el)·cos(az)·len, y = cos(el)·sin(az)·len, z = sin(el)·len
  • Two mutually exclusive input forms: a combined array az holding geographic coordinates (3, n, m), or separate az, el, len of shape (n, m)
  • For combined input, row 0 = azimuth, row 1 = elevation, row 2 = length
  • len is optional in separate mode; omit it for unit length
  • Inverse of cart2geo; round-trips in both the combined and separate forms
  • The AVX2 kernel computes sine and cosine in single precision (angles reduced in double precision first; max. error about 1.3e-7 for angles up to 1e10); use use_kernel = 1 for full double precision
Usage:
cart    = quadriga_lib.tools.geo2cart( az, el, len, combine, use_kernel )
x, y, z = quadriga_lib.tools.geo2cart( az, el, len, combine=False )
Inputs:
  • az — Azimuth angles (n, m); or, when el is omitted, combined geographic coordinates (3, n, m) (row 0 = azimuth, row 1 = elevation, row 2 = length)
  • el — Elevation angles (n, m); omit for combined input; default: None
  • len — Vector length (n, m); omit for unit length; ignored for combined input; default: None
  • combine — If True, return a single (3, n, m) array; if False, return separate x, y, z arrays; default: True
  • use_kernel — Kernel: 0 = auto (AVX2 if available, else GENERIC), 1 = GENERIC, 2 = AVX2 (throws if unavailable); other values raise; default: 1
Outputs:
  • cart — Combined Cartesian coordinates (3, n, m); row 0 = x, row 1 = y, row 2 = z; returned when combine is True
  • x — X-coordinates (n, m); returned when combine is False
  • y — Y-coordinates (n, m); returned when combine is False
  • z — Z-coordinates (n, m); returned when combine is False

calc_diffraction_gain
Calculate diffraction gain for multiple TX-RX pairs using a 3D triangular mesh
  • Estimates diffraction gain by evaluating Fresnel ellipsoid obstruction; each TX-RX path is divided into n_path elliptic-arc paths (controlled by lod), each approximated by n_seg line segments
  • Segment attenuation is combined via weighted summation calibrated to 2D UTD coefficients, generalized to arbitrary 3D shapes
  • Optional sub-mesh indexing (see triangle_mesh_segmentation) accelerates computation by skipping triangles whose bounding box does not intersect the TX-RX path
  • The material model and its columns: The quadriga-lib Material Model and Ray-Surface Physics; the CSV format of the material table: Data Formats
Usage:
# Output as tuple
data = quadriga_lib.RTtools.calc_diffraction_gain( orig, dest, mesh, mtl_ind, mtl_prop, \
    center_frequency, lod, verbose, sub_mesh_index, use_kernel, gpu_id, scalar_mode, \
    thin_slab_threshold, apply_fspl, apply_phase )

# Unpacked outputs
gain, xprmat, coord = quadriga_lib.RTtools.calc_diffraction_gain( orig, dest, mesh, mtl_ind, mtl_prop, \
    center_frequency, lod, verbose, sub_mesh_index, use_kernel, gpu_id, scalar_mode, \
    thin_slab_threshold, apply_fspl, apply_phase )
Inputs:
  • orig — TX positions; (n_pos, 3)
  • dest — RX positions; (n_pos, 3)
  • mesh — Triangle vertices, each row [X1,Y1,Z1,X2,Y2,Z2,X3,Y3,Z3]; (n_mesh, 9)
  • mtl_ind — 1-based material index per face (0 = no material; the csv_ind output of obj_file_read); (n_mesh,)
  • mtl_prop — Material properties as a dict; each key is one column (the csv_prop output of obj_file_read) mapping to a 1D array of length n_mtl
  • center_frequency — Center frequency
  • lod — Level of detail (0–7), controls n_path and n_seg: 0 = direct ray only (1 path, 1 segment); 1 / 2 = 7 / 19 paths with 3 segments; 3 = 37 paths, 4 segments; 4 = 61 paths, 5 segments; 5 / 6 = 1 / 2 paths with 2 segments (debug); 7 = direct line in 10 segments; default: 2
  • verbose — Verbosity level; default: 0
  • sub_mesh_index — 0-based sub-mesh index for acceleration; see triangle_mesh_segmentation; (n_mesh,) or None; default: None
  • use_kernel — Kernel selection: 0 = auto, 1 = GENERIC, 2 = AVX2, 3 = CUDA; error if unavailable; default: 0
  • gpu_id — CUDA device ID; ignored for non-CUDA kernels; default: 0
  • scalar_mode — If True, uses scalar transmission (TE-only reflection coefficient, energy-conservation transmission) instead of EM TE/TM averaging; default: False
  • thin_slab_threshold — Thin-slab (Fabry-Pérot) resolve threshold; 0 = resolve always, 1 = resolve never; see ray_state_update; default: 0
  • apply_fspl — If True, folds the geometric spreading loss into gain, making it an absolute propagation gain instead of a value relative to FSPL. The reference distance is the direct TX-RX distance, matching the path_length used by qrt_file_read for a transmission-only path. EM mode: 32.45 + 20log10(f_GHz) + 20log10(d_m) dB; scalar mode: 20log10(d_m) + alpha(f)d_m dB, with alpha from ISO 9613-1 at T = 20 °C, RH = 50 %, p = 1 atm.; default: False
  • apply_phase — If True, multiplies xprmat by the propagation phase exp(-j2pi*d/lambda) using the same direct TX-RX distance. The wavelength follows from center_frequency and the medium wave speed (speed of light in EM mode, speed of sound in scalar mode). The term has unit magnitude, so xprmat stays normalized. This is the phase get_channels_spherical would otherwise add from path_length; default: False
Outputs:
  • gain — Diffraction gain per TX-RX pair, linear power scale; (n_pos,). Relative to FSPL by default (bounded by 0 and 1), absolute propagation gain when apply_fspl = True
  • xprmat — Normalized polarization transfer matrix: the amplitude carries no path gain (max column power is 1), only the relative polarization coupling and phase; gain holds the power. EM mode: interleaved complex, column-major [ReVV ImVV ReHV ImHV ReVH ImVH ReHH ImHH] with labels <rx><tx>: rows 0-1 = (V rx, V tx), rows 2-3 = (H rx, V tx), rows 4-5 = (V rx, H tx), rows 6-7 = (H rx, H tx), the row order of M in get_channels_spherical, (8, n_pos); scalar mode: scalar pressure coefficient [Re Im], (2, n_pos)
  • coord — Diffracted path coordinates excluding endpoints; (3, n_seg-1, n_pos) with n_seg from lod (e.g. (3, 2, n_pos) for lod 2, (3, 9, n_pos) for lod 7, (3, 0, n_pos) for lod 0)
See also:

cube
Construct a triangulated cube mesh
  • Generates a Blender-style cube: a 2 x 2 x 2 box centered at the origin (vertices at +/-1)

Sum-of-sinusoids random number generator

These functions generate spatially correlated random numbers: values that are random, but similar at nearby positions. Two positions that are much closer than the decorrelation distance get almost the same value, two positions that are far apart get independent values. The decorrelation distance is the distance at which the correlation has fallen to exp(-1), about 0.37. Typical uses are shadow fading maps and the spatially consistent parameters of the 3GPP TR 38.901 channel model.

The values are a sum of sinusoids, s(x) = sqrt(2/N) · sum_n cos( 2·pi · f_n·x + phi_n ). The frequencies f_n set how the correlation falls with the distance, i.e. the autocorrelation function (ACF). The random phases phi_n select one realisation of the random field. The generator needs no map and no grid: positions can be anywhere, in 1, 2 or 3 dimensions, and the same frequencies and phases always give the same field.

The functions are in the submodule quadriga_lib.sos: sos.val is called as quadriga_lib.sos.val. In the examples, np is numpy.

Quick start
sos.randn sets up the generators, draws the phases and returns the values in one call. sos.rand and sos.randi do the same for Uniform and integer values. 
# 1000 positions; one row per position, columns are (x, y, z) in meters
pos = np.random.default_rng(0).random((1000, 3)) * 100

# One independent generator per decorrelation distance: 10 m and 50 m
dist_decorr = [10, 50]

# Normal distributed values with zero mean and unit variance, shape (1000, 2)
val = quadriga_lib.sos.randn(dist_decorr, pos, seed=42)

# Uniform values between 0 and 1, and integers from 1 to 6
uni = quadriga_lib.sos.rand(dist_decorr, pos, seed=42)
dice = quadriga_lib.sos.randi(dist_decorr, pos, 6, seed=42)
The argument seed is the seed. With the same seed, decorrelation distances and preset, a later call returns the same field, also at other positions. Without a seed every call gives a new field. The functions have their own random stream; the random state of numpy has no effect on them.

A seed selects a set of phases, not a field. Calls with the same seed but another decorrelation distance or another preset return related fields: they are equal at the coordinate origin and correlated around it. Quantities that must be independent of each other, such as shadow fading and delay spread, therefore need different seeds, or one call with one entry of dist_decorr per quantity: the generators of one call are independent.

Keeping a generator
A generator is two arrays: the frequencies from sos.preset and the phases from sos.init_phases. sos.val evaluates them. Each column of the phase array is one independent generator. Evaluating many generators in one call is much cheaper than one call per generator, because the sines and cosines of the positions are shared: 20 generators take less than twice as long as one. 
# Frequencies of a predefined generator for a decorrelation distance of 10 m
freq, acf, dist = quadriga_lib.sos.preset("Comb256", 10)

# Phases of 20 generators; each column is one independent random field
phase = quadriga_lib.sos.init_phases(freq.shape[0], 20, 42)

# Values of all 20 generators at the positions, shape (1000, 20)
val_all = quadriga_lib.sos.val(freq, phase, pos)

# The same fields at other positions, at any later time
pos_new = pos + 2.5
val_new = quadriga_lib.sos.val(freq, phase, pos_new)

# Uniform distributed output
val_uni = quadriga_lib.sos.val(freq, phase, pos, uniform=True)

# Map on a regular grid, shape (n_y, n_x, 1, 20); the first generator is saved as an image
x = np.arange(0, 250.5, 0.5)
y = np.arange(0, 100.5, 0.5)
grid = quadriga_lib.sos.map(freq, phase, x, y)
quadriga_lib.tools.write_png("map.png", grid[:, :, 0, 0])
  • Positions: one row per position, (n_pos, 3). Results have one row per position and one column per generator, (n_pos, n_gen). A one-dimensional array is one coordinate per position: [x, y, z] is three positions on the x-axis; one position is a two-dimensional array with one row.
  • Presets: Exp, Gauss and Comb, each with 128, 256, 512 or 1024 sinusoids, e.g. "Exp512". Exp is the exponential ACF exp(-d/d0), Gauss is exp(-(d/d0)^2), and Comb follows Gauss up to the decorrelation distance d0 and Exp beyond it. Each doubling of the number of sinusoids doubles the computing time and lowers the error of the ACF by 3 to 4 dB: sos.calc_mse reports 28, 31, 34 and 38 dB for Exp128 to Exp1024 and 31, 35, 39 and 42 dB for Comb128 to Comb1024. "Comb256" is a good default; take a larger table if the shape of the ACF matters, a smaller one if speed does.
  • Both ends mobile: if a value belongs to a link between two moving devices, pass both positions. The value then changes smoothly when either device moves.
# Positions of the two ends of 1000 links; one value per link and generator, shape (1000, 20)
pos_tx = pos
pos_rx = np.random.default_rng(1).random((1000, 3)) * 100
val_link = quadriga_lib.sos.val(freq, phase, pos_tx, pos_rx, acf=acf, dist=dist)
  • Mean over an area: the values at positions that lie within a few decorrelation distances of each other are similar, so their average is not zero for a single realisation. This is how a correlated field behaves. sos.remove_bias can force the average to zero if an application needs it. This removes variance: for 200 positions in a square with an edge of 20 decorrelation distances 2.5 %, for an edge of 5 decorrelation distances 14 %, for 2 already 44 %. It is meant for positions that spread over many decorrelation distances.
  • Coordinates: use local coordinates. The argument f_n·x of a sinusoid is computed in double precision and is known to about 1e-16 of its size, so the values lose accuracy with the distance from the origin counted in wavelengths. Up to 1e9 wavelengths (more than 1e9 m for a decorrelation distance of 10 m) the results stay within the tolerance stated in sos.val.
  • Threads and memory: the functions that take noticeable time use the OpenMP threads of the process, except sos.generate, which runs on one thread. No result depends on the number of threads. sos.val computes in its output: it needs no further memory of that size for one device and one more array of that size for two devices.
Own autocorrelation functions
sos.generate finds the frequencies for any ACF that is given as a table over the distance, and sos.calc_mse reports how well the result fits. The table should reach to about 5 decorrelation distances. 
# Target ACF from 0 to 5 decorrelation distances, here a Gaussian shape with 5 m
dist_own = np.arange(200) * 0.125
acf_own = np.exp(-np.square(dist_own / 5))

# 256 sinusoids in 3-D, 300 test directions, wavelengths up to 20 decorrelation distances (100 m)
freq_own, ase, test_dir = quadriga_lib.sos.generate(acf_own, dist_own, 256, n_dir=300, freq_min=0.01, seed=1)

# Approximation error in dB, larger is better; about 35 dB for this example
mse, mse_core, mse_all, acf_tail, test_dir = quadriga_lib.sos.calc_mse(freq_own, acf_own, dist_own)
The result is used like a preset: draw phases with sos.init_phases and evaluate with sos.val. To change the decorrelation distance afterwards, divide the frequencies and multiply the distances by the same factor.

sos.acf_approx
ACF produced by a set of sinusoids

  • The output is always 3-dimensional
  • n_dim = 1: along the axis; (n_grid, 1, 1)

sos.acf_estimate
Monte-Carlo estimate of the ACF of one generator
  • Estimates the autocorrelation function (ACF) of one realisation of a generator from its values at random positions
  • Draws 2·n_pos positions, uniformly in a cube with half edge 0.4·max(bins) around the origin, evaluates the generator there, and for each distance bin computes the correlation coefficient between the two values of all position pairs whose distance falls into the bin
  • Positions: an array (2·n_pos, 3) is filled column by column (all x, then all y, then all z) with ( 2·u - 1 ) · 0.4·max(bins), where u comes from the random stream described in sos.init_phases
  • Bin n covers the distances from the midpoint between bins[n-1] and bins[n] (excluded) to the midpoint between bins[n] and bins[n+1] (included). The first bin starts at 1e-5 m, the last bin ends half a mean bin spacing above bins[-1]
  • Bins with fewer than 6 pairs return NaN in all outputs
  • acf_est_dual: the same for two devices on the same map. The first n_pos positions are the first device, the second n_pos positions the second device, and the value of a link is sos.val with both positions. Two links form a pair if the distance between their first devices falls into the bin and the distance between their second devices does not exceed the upper limit of the bin; requires acf and dist
  • acf_est_dual is computed if acf or dist is given, and is None if both are omitted; giving only one of the two is an error
  • The estimate describes one realisation; it scatters around the ACF of the sinusoids
  • Run time grows with n_pos^2; the result does not depend on the number of threads
Usage:

    acf, dist, seed )
Inputs:
  • freq — Frequencies; (n_coeff, 3)
  • phase — Phases of the generator; (n_coeff,) or (n_coeff, 1)
  • bins — Bin centers; must be >= 0, increase strictly and be finite; at least 2 elements; (n_bin,)
  • n_pos — Number of random positions per device; int; must be > 1
  • acf — Target ACF; required for acf_est_dual, must then be > -1; (n_acf,); default: None
  • dist — Sample points of the ACF; must start at 0, increase strictly and be finite; (n_acf,); default: None
  • seed — Seed for the positions; int; must be >= -1; -1 seeds from the system random device; default: -1
Outputs:
  • acf_est — Estimated ACF; (n_bin,)
  • dist_est — Mean distance of the pairs in each bin; (n_bin,)
  • acf_est_dual — Estimated ACF for two devices on the same map; (n_bin,); None if acf and dist were not given

sos.calc_mse
Approximation error of the ACF of a set of sinusoids
  • Compares the autocorrelation function (ACF) produced by the sinusoids, R(dx) = (1/n_coeff) · sum_n cos( 2·pi · f_n·dx ), with the target ACF
  • All errors are returned as -10·log10( mean squared error ); larger is better
  • mse: error along the test directions on the sample points dist. n_dim = 1: one direction; n_dim = 2: n_dir directions equally spaced on the half circle, azimuth pi · i / n_dir; n_dim = 3: n_dir directions on a spiral (Fibonacci) lattice on the upper hemisphere, sin(elevation) = ( i + 0.5 ) / n_dir, azimuth i · pi · ( 3 - sqrt(5) ), with i counted from 0. A direction and its opposite give the same ACF
  • mse_core: error on the grid of sos.acf_approx against sos.acf_2d, for the grid points within a radius of n_acf grid steps around the center; for n_dim = 3 the mean squared error is averaged over the three planes
  • mse_all: same on the complete grid, which extends to 2·Dmax and has a target of 0 beyond Dmax
  • For n_dim = 1, mse_core is evaluated on the sample points dist, mse_all on the axis from -2·Dmax to 2·Dmax, and mse equals mse_core
  • acf_tail: approximated ACF, averaged over the test directions, at 2, 4, 10 and 20 times Dmax. The target is 0 there; sinusoids with a frequency near zero show up as a plateau of height n_low / n_coeff, which adds a constant offset to all values of a large area
  • All outputs are always computed, including the 2-D grids behind mse_core and mse_all
  • A perfect fit has a mean squared error of 0 and is returned as inf; this happens for a target that the sinusoids reproduce exactly at all sample points
  • Equally spaced has the meaning given in sos.acf_2d
Usage:
mse, mse_core, mse_all, acf_tail, test_dir = quadriga_lib.sos.calc_mse( freq, acf, dist, n_dir )
Inputs:
  • freq — Frequencies; n_dim = 1, 2 or 3; (n_coeff, n_dim)
  • acf — Target ACF; at least 2 elements; (n_acf,)
  • dist — Sample points of the ACF; must start at 0, be equally spaced and finite; (n_acf,)
  • n_dir — Number of test directions; int; must be > 0; ignored for n_dim = 1; default: 10
Outputs:
  • mse — Error along the test directions in [dB]; float
  • mse_core — Error within the core radius in [dB]; float
  • mse_all — Error on the complete grid in [dB]; float
  • acf_tail — Approximated ACF beyond the fitted range; (4,)
  • test_dir — Test directions; (n_dir, 2) with columns (azimuth, elevation) for n_dim = 3; (n_dir, 1) with the azimuth for n_dim = 2; empty (0, 0) for n_dim = 1
See also:
  • sos.generate (finds the frequencies; minimises the error returned here)
  • sos.acf_approx, sos.acf_2d (the two grids that are compared)

sos.generate
Find the frequencies of a sum-of-sinusoids generator for a given ACF
  • Searches n_coeff frequencies such that the autocorrelation function (ACF) of the sinusoids, R(dx) = (1/n_coeff) · sum_n cos( 2·pi · f_n·dx ), approximates the target ACF in all directions
  • Each sinusoid has a fixed direction and a signed frequency along it. n_dim = 1: no direction; n_dim = 2: directions on the half circle; n_dim = 3: directions on the upper hemisphere. uniform_smp = True places them regularly (equally spaced azimuth, spiral lattice, as the test directions of sos.calc_mse), False draws them at random
  • Iteration: in each pass every sinusoid is re-fitted once. Its frequency is chosen to fit the residual between the target and the contribution of all other sinusoids along its own direction: coarse search over a grid with a spacing of 0.1 / max(dist), then a step refinement. The new frequency is kept only if the mean squared error over the test directions decreases. The iteration stops after a pass that changes nothing or lowers the error by less than a factor of 1e-6, or after 1000 passes
  • random_init = True starts from uniformly random frequencies; False builds the set up sinusoid by sinusoid in the first pass
  • The fit covers the range of dist only. The ACF of the result beyond the last sample point is not controlled; sinusoids with a frequency near zero keep it above zero at all larger distances (see acf_tail of sos.calc_mse). To prevent this, set freq_min
  • freq_min and freq_max limit the magnitude of the frequency along the direction of each sinusoid; 0 selects the default: no lower limit, and 15 / max(dist) as upper limit
  • The search grid has ( freq_max - freq_min ) · max(dist) / 0.1 + 1 points, and its cosines are stored for all sample points. It must not have more than 100000 points (the default has 151), which limits freq_max - freq_min to less than 10000 / max(dist)
  • The function runs on one thread
  • Use enough test directions: with few (e.g. 10) the result fits those directions and is worse in others; the predefined tables of sos.preset were made with 300
  • A seed >= 0 makes the result repeatable on one platform. The search takes accept/reject decisions, so a difference in the last bit of the input or of the math library can lead to another table of equivalent quality
Usage:
freq, ase, test_dir = quadriga_lib.sos.generate( acf, dist, n_coeff, n_dim, uniform_smp, n_dir, \
    random_init, freq_min, freq_max, seed )
Inputs:
  • acf — Target ACF; at least 2 elements; (n_acf,)
  • dist — Sample points of the ACF; must start at 0, increase strictly and be finite; (n_acf,)
  • n_coeff — Number of sinusoids; int; must be > 0
  • n_dim — Number of dimensions; int; 1, 2 or 3; default: 3
  • uniform_smp — Regular (True) or random (False) directions of the sinusoids; default: True
  • n_dir — Number of test directions; int; must be > 0; ignored for n_dim = 1; default: 10
  • random_init — Start from random frequencies (True) or build up sinusoid by sinusoid (False); default: True
  • freq_min — Lower limit of the frequency magnitude; must be >= 0; 0 = none; default: 0.0
  • freq_max — Upper limit of the frequency magnitude; must be >= 0 and, if not 0, larger than freq_min; 0 = 15 / max(dist); limited by the size of the search grid, see above; default: 0.0
  • seed — Seed; int; must be >= -1; -1 seeds from the system random device; default: -1
Outputs:
  • freq — Frequencies; (n_coeff, n_dim)
  • ase — Mean squared error over the test directions after each pass, linear scale; (n_pass,)
  • test_dir — Test directions; (n_dir, 2) with columns (azimuth, elevation) for n_dim = 3; (n_dir, 1) with the azimuth for n_dim = 2; empty (0, 0) for n_dim = 1
See also:
  • sos.calc_mse (error of a frequency table)
  • sos.preset (precomputed tables)

sos.preset
Frequencies and ACF of a predefined sum-of-sinusoids generator
  • Returns a precomputed frequency table for sos.val together with the autocorrelation function (ACF) it was fitted to
  • Presets: "Exp128", "Exp256", "Exp512", "Exp1024", "Gauss128", "Gauss256", "Gauss512", "Gauss1024", "Comb128", "Comb256", "Comb512", "Comb1024". The number is the number of sinusoids, n_coeff. The name is matched exactly, including upper and lower case

  • All tables are 3-dimensional and can be used with positions of 1, 2 or 3 columns
  • No sinusoid has a wavelength above 20 decorrelation distances. The ACF of the tables stays near zero beyond the fitted range, and the mean of the generator over a large area is not offset by sinusoids of nearly zero frequency

sos.rand
Spatially correlated Uniform distributed random numbers
  • Convenience function: sets up one sum-of-sinusoids generator per entry of dist_decorr from a preset, draws its phases and evaluates it at the given positions; see sos.val for the model
  • The generators are independent of each other and may have different decorrelation distances
  • Phases: generator g uses column g of quadriga_lib.sos.init_phases( n_coeff, n_gen, seed ). A second device on its own map uses column g of a second stream, quadriga_lib.sos.init_phases( n_coeff, n_gen, seed_b ), where seed_b is the seed with bit 62 flipped, i.e. seed + 2^62 for seeds below 2^62; for seed = -1 both streams are random. The phases of a generator therefore depend neither on the number of generators nor on whether a second device is given
  • A decorrelation distance of 0 is replaced by 0.1 m
  • One device (pos_b omitted): values of the generator at pos
  • Two devices, same decorrelation distance (dist_decorr_b omitted, or equal to dist_decorr for that generator): both devices are on the same map, the value does not change when they swap positions
  • Two devices, different decorrelation distances: each device has its own map; the value is the sum of both maps divided by sqrt(2)
  • The Normal distributed value s of the generator is mapped to 0.5 · erfc( -s / sqrt(2) )
  • Each call with seed = -1 gives a new realisation. With a seed >= 0 the phases are the same on all platforms: the same positions give the same values and nearby positions similar values, also in separate calls. The kernel is chosen automatically, so values from machines with and without AVX2 differ by the tolerance stated in sos.val. The random state of numpy is not used
  • A seed selects the phases, not the field: calls with the same seed but other decorrelation distances or another preset return related fields, equal at the coordinate origin and correlated around it. Use different seeds, or several entries of dist_decorr in one call, for quantities that must be independent
  • An optional array that is None or empty counts as not given

Inputs:

  • pos — Positions of the first device; one row per position; the number of columns sets the number of dimensions: (n_pos, 1) = (x), (n_pos, 2) = (x, y) or (n_pos, 3) = (x, y, z); coordinates that are not given are 0; a 1-D array is one column, i.e. one x-coordinate per position
  • pos_b — Positions of the second device; None = one device; (n_pos, 1), (n_pos, 2) or (n_pos, 3) as for pos; the number of columns may differ from pos; default: None
  • dist_decorr_b — Decorrelation distances of the second device; requires pos_b; must be >= 0; None = same as dist_decorr; (n_gen,); default: None
  • preset — Name of the preset, see sos.preset; str; default: "Comb256"
  • seed — Seed of the phases; int; must be >= -1; -1 seeds from the system random device; default: -1

  • val — Values, approximately Uniform distributed between 0 and 1; one row per position, one column per generator; (n_pos, n_gen)

sos.randn
Spatially correlated Normal distributed random numbers
  • Convenience function: sets up one sum-of-sinusoids generator per entry of dist_decorr from a preset, draws its phases and evaluates it at the given positions; see sos.val for the model
  • The generators are independent of each other and may have different decorrelation distances
  • Phases: generator g uses column g of quadriga_lib.sos.init_phases( n_coeff, n_gen, seed ). A second device on its own map uses column g of a second stream, quadriga_lib.sos.init_phases( n_coeff, n_gen, seed_b ), where seed_b is the seed with bit 62 flipped, i.e. seed + 2^62 for seeds below 2^62; for seed = -1 both streams are random. The phases of a generator therefore depend neither on the number of generators nor on whether a second device is given
  • A decorrelation distance of 0 is replaced by 0.1 m
  • One device (pos_b omitted): values of the generator at pos
  • Two devices, same decorrelation distance (dist_decorr_b omitted, or equal to dist_decorr for that generator): both devices are on the same map, the value does not change when they swap positions
  • Two devices, different decorrelation distances: each device has its own map; the value is the sum of both maps divided by sqrt(2)
  • Each call with seed = -1 gives a new realisation. With a seed >= 0 the phases are the same on all platforms: the same positions give the same values and nearby positions similar values, also in separate calls. The kernel is chosen automatically, so values from machines with and without AVX2 differ by the tolerance stated in sos.val. The random state of numpy is not used
  • A seed selects the phases, not the field: calls with the same seed but other decorrelation distances or another preset return related fields, equal at the coordinate origin and correlated around it. Use different seeds, or several entries of dist_decorr in one call, for quantities that must be independent
  • An optional array that is None or empty counts as not given

sos.remove_bias
Remove the sample mean of sum-of-sinusoids generators over a set of positions
  • One realisation of a spatially correlated random field has a non-zero mean over a finite set of positions. Its variance over the realisations is the mean of the autocorrelation function (ACF) over all pairs of positions, which is much larger than 1 / n_pos when the positions lie within a few decorrelation distances of each other. This is a property of any correlated field, not an error of the generator
  • This function adds one offset to all phases of a generator such that the mean of the Normal distributed values of sos.val over the given positions becomes zero
  • Closed form, no iteration: with z_n = mean over the positions of exp( j·2·pi · f_n·x ) and Z = sum_n z_n · exp( j·phi_n ), the mean is sqrt(2/n_coeff) · Re( exp( j·offset ) · Z ), which vanishes for offset = pi/2 - arg(Z) and for that value minus pi; the one with the smaller magnitude is applied, so the offset lies between -pi/2 and pi/2
  • One device (pos_b omitted): one offset per generator
  • Two devices on the same map (pos_b given, phase_b_in omitted): one offset per generator that zeroes the mean of the combined, normalised value; acf and dist are required
  • Two devices on different maps (pos_b and phase_b_in given): each device is treated on its own, phase_in with pos and phase_b_in with pos_b and the frequencies freq · freq_scale_b; two offsets per generator. The mean of the combined value is then zero as well
  • Effect on the statistics: the result is the field conditioned on a zero mean over the positions. The variance at a position drops from 1 to 1 - c^2 / v, where v is the variance of the sample mean and c the mean ACF between that position and all positions; on average over the positions the loss is at least v. It is small only if the positions spread over many decorrelation distances. For positions within about one decorrelation distance most of the variance is removed
  • The zero mean holds for exactly these positions and frequencies. It is lost when the phases are used with other frequencies (another decorrelation distance) or positions
  • Rule of thumb, measured for 200 positions in a square with the edge L and the decorrelation distance d (Comb256): the variance drops by 74 % for L = d, 44 % for L = 2·d, 14 % for L = 5·d, 5 % for L = 10·d, 2.5 % for L = 20·d and less than 1 % from L = 50·d on
  • Phases are returned in the interval from -pi (included) to pi (excluded). A generator whose abs(Z) is below 1e-14 · n_coeff already has a zero mean for every offset and is returned unchanged, also if its phases lie outside that interval
  • Two devices on the same map need an ACF above -1 at all sample points, as in sos.val
  • The input arrays phase_in and phase_b_in are not modified; the corrected phases are new arrays
  • An optional array that is None or empty counts as not given
Usage:

    pos_b, phase_b_in, acf, dist, freq_scale_b )
Inputs:
  • freq — Frequencies; n_dim = 1, 2 or 3; (n_coeff, n_dim)

  • pos_b — Positions of the second device; None = one device; (n_pos_b, 1), (n_pos_b, 2) or (n_pos_b, 3) as for pos; n_pos_b = n_pos for the same map, any number for different maps; default: None
  • phase_b_in — Phases of the second device; requires pos_b; None = same map; (n_coeff, n_gen); default: None
  • acf — Target ACF; required for two devices on the same map, must then be > -1; (n_acf,); default: None
  • dist — Sample points of the ACF; must start at 0, increase strictly and be finite; (n_acf,); default: None

sos.val
Spatially correlated random values at given positions
  • Sum-of-sinusoids generator: at position x a generator with n_coeff sinusoids produces s(x) = sqrt(2/n_coeff) · sum_n cos( 2·pi · f_n·x + phi_n ), with the frequencies f_n (rows of freq, in cycles per meter) and the phases phi_n (one column of phase)
  • For uniformly random phases, s has zero mean, unit variance and the autocorrelation function (ACF) (1/n_coeff) · sum_n cos( 2·pi · f_n·dx ), which approximates the target ACF the frequencies were fitted to; with many sinusoids the values are approximately Normal distributed
  • All generators of one call share the frequencies; each column of phase is one generator. The sines and cosines of the positions are computed once and reused for all generators
  • Positions are given as one row per position with the columns (x, y, z); they may have fewer columns than freq; missing coordinates are 0
  • One device (pos_b omitted): val = s(pos)
  • Two devices on the same map (pos_b given, phase_b omitted): both devices use phase; val = ( s(pos) + s(pos_b) ) / sqrt( 2 + 2·A(D) ), where D is the distance between pos and pos_b and A the target ACF interpolated as in sos.acfi; acf and dist are required. The value does not change when the two devices swap their positions
  • Two devices on different maps (pos_b and phase_b given): val = ( s_a(pos) + s_b(pos_b) ) / sqrt(2); s_b uses phase_b and the frequencies freq · freq_scale_b; acf and dist are ignored
  • The mode follows from the arguments only; phase values are never compared. Passing the same array as phase and phase_b selects the two-map formula
  • freq_scale_b other than 1 requires phase_b: one map with two decorrelation distances has no consistent ACF
  • Two devices on the same map need an ACF above -1 at all sample points, because the value is divided by sqrt( 2 + 2·A(D) )
  • uniform = True maps the values to 0.5 · erfc( -val / sqrt(2) ), which is uniform between 0 and 1 as far as val is Normal distributed. The limits 0 and 1 are included: a value far out in the tail is rounded to them
  • Kernels: GENERIC computes in double precision. AVX2 evaluates sine and cosine in single precision; its values differ from GENERIC by less than 4e-7 · sqrt( 2·n_coeff ), typically by less than 1e-6
  • Accuracy far from the origin: the argument f_n·x is known to about 1e-16 of its size. The bound between the kernels holds up to about 1e9 periods of the sinusoids; beyond that both kernels lose accuracy at the same rate
  • A NaN or infinite coordinate gives NaN at that position and does not affect other positions
  • The value at a position does not depend on the other positions or generators of the call, nor on the number of threads
  • An optional array that is None or empty counts as not given
